# Sked adaptive workbench design

## Authority
Material 3 Expressive, semantic ColorScheme roles and exact saved user colors remain authoritative. Reference screenshots inform hierarchy and continuity, not imitation. No new UI, routing or state framework.

## Composition
Student timetables lead with the complete time canvas. General day/week views lead with the calendar; selected-day agenda is opt-in. Compact month leads with its calendar and places the selected-day agenda below in one scroll surface; wide month keeps an event-rich calendar and a supporting agenda. List uses list/detail without a duplicated agenda. A single enabled workspace removes mode chrome, not settings access.

## Continuous surfaces
Use two continuous structural roles, resolved through SkedSurface: content uses ColorScheme.surface; navigation, the complete toolbar and docked panes use surfaceContainerLow. Caption clearance, pane headers, nested routes, safe areas and footers must inherit the same role instead of exposing a different background. A docked editor inherits frame; the same editor presented independently inherits content without recreating its draft. Independent dialogs/pickers explicitly reset the role. Structural surfaces have no tint or scrolled-under recoloring; retain modal scrims and shadows. Separate ordinary groups with spacing and hairlines, not extra filled cards. Controls, selected/hovered/error states and saved event colors remain semantic and unchanged. Desktop controls are compact; touch targets remain at least 48 dp.

## Task budgets
Window classes remain 600/840/1200 dp, not device classifications. WorkbenchLayoutPolicy owns actual pane decisions. Resources: 224 dp, compact: 56 pointer / 80 touch. Integrated resource navigation animates width and clipped label/content reveal using the shared motion policy. Expanded and compact states retain the same row heights, icon sizes, leading slots, focus nodes and hit targets; the bottom Settings anchor does not move vertically. Reduced motion settles directly. An in-flight transition never consumes the minimum canvas or newly docked task budget. Detail: 360, assistant: 400, base canvas: 600, seven-day calendar docking budget: 800. Forms use 224 navigation + 520 content, so an 800 dp portrait tablet can show the settings group index and editable overview even when its calendar stays a single task. Scale budgets with text; never shrink text to preserve a column.

Collapse resource navigation before overlaying detail, then overlay the independent assistant. Preserve intended widths and open states through automatic fallback. Only the top visible overlay receives focus. Calendar horizontal scrolling and week paging must not compete. General-calendar resources use the category icon to open management and the plus action to add; omit the redundant category-header More menu. Import/export remains explicitly available in Settings.

Compact workspace navigation keeps the official Material NavigationBar, a 64 dp content height and exactly one bottom safe inset. Content and system area share surfaceContainerLow: do not paint a separate gesture strip. The persistent selected capsule is transparent; filled icons, a readable theme-family accent and moderate label weight indicate selection. Both icons have a 4 dp optical downward offset; labels and full destination touch targets keep Material's layout and semantics. Only this bottom bar opts out of splash, press and hover ink; keyboard focus remains visible and activation still uses the official destinations. Keep the existing 1.3 maximum label scale, center wrapped lines and measure resolved styles to grow for genuine wrapping. Check actual glyphs rather than treating indicator rectangles as proof of visual centering. Android owns the real gesture handle; request matching system icon brightness. Rails are unchanged.

## Desktop category management
The desktop category entry opens an adjacent transparent-modal task, not a full page or an independent view window. Prefer right from resource navigation and below from toolbar/menu triggers; only a genuinely missing initial anchor centers. Use the shared 8 dp surface, 6 dp anchor gap and 8 dp safe margin. Prefer 440 dp width, at most 520 dp with larger text; cap the scrollable list near 400 dp, keeping the header and transfer actions reachable. A single compact row contains color, a two-line rename target, event count/explicit hidden status, unfilled visibility icon button and More (rename/delete). The labeled create action wraps below the draggable title when needed. Resources stay fixed; their plus opens a name draft directly.

Management has no aggregate save: visibility persists immediately with rollback; name and color confirm their own drafts. Color reuses the theme picker, six existing theme slots, HSV/hue and validated Hex. Untouched theme slots never become resolved RGB. Color persistence takes only category ID and color and patches current data, never an opening snapshot. Parent/child guards retain drafts on failure, consume outside clicks and prevent closure/repeated submit while busy. Data/target/workspace invalidation retires owned routes, including nested discard confirmation; cleanup must tolerate an already removed route. Import/export closes management, awaits its exit animation, then opens the existing transfer workflow without resurrecting management on return. Touch pages, dangerous confirmation semantics, storage and backup formats remain unchanged. See docs/DESKTOP_FLOATING_PANELS.md for verification and the explicitly outstanding native mouse check.

## Windows chrome
One integrated application/window row, not a second title bar. Native Win32 retains resize, move, maximize, system menu, close and HTMAXBUTTON snap semantics. Application controls must win hit tests over drag regions. The application detail-pane close button has 8 dp outer padding on all sides below the caption row; it is distinct from the OS close button. Close awaits draft guards and pending saves. Android keeps its own safe areas, Back and IME behavior, never Windows caption buttons.

## Stable tasks and AI preview
Editors own drafts independently of their presentation. Ordinary workspace switching, settings visits and rotation do not discard drafts. Full data replacement must retire old editor sessions even if their workspace remains enabled. AssistantPaneController is independent from the detail navigator. The assistant panel starts closed on every launch. DeveloperUiPreferences stores feature enablement (entry availability), not panel visibility, outside AppData and backups; a saved choice overrides SKED_AI_LAYOUT_PREVIEW. Loading, retrying or enabling the feature never opens a panel. Only an explicit toolbar action opens it; disabling the feature closes it. Closing a panel preserves feature enablement and the current session draft. A preview only displays read-only context and an unsent session draft, never fake AI actions.

Compact month dates use 48 dp rows without lunar captions and 56 dp with them at ordinary text sizes, with a roughly 36 dp weekday header. Grow from real text metrics at large scales; the decorative selected shape must not constrain date glyphs. Large lunar captions may wrap; date numerals never become empty ellipses. Reserve event-marker space uniformly. Selecting another day in the month updates the agenda without scrolling; changing months reveals the calendar. Empty agenda is one line, not a fixed-height illustration panel.

## Settings and workflows
Period-time-set editing is a bounded chronological list, not a grid of decorated cards. Wide rows share measured period/start/end/duration/break/action columns; compact rows prioritize the time range and put duration/gap in secondary text. Never truncate times or validation messages to preserve a column. Keep the existing 24-hour picker and serialized auto-save semantics. Reserve localized save-status space so pending, saving, failed and invalid drafts do not shift the list; invalid drafts take precedence over any saved indication. One lightweight append action lives after the final row and reveals the new period. Resizing and deletion above the viewport preserve the visible period, not just the scroll pixel count.

Desktop category management opens a compact, title-draggable transparent-modal panel beside its stable trigger; touch devices retain the category page. Prefer 440 dp width (up to 520 dp at larger text scales) and a bounded, scrollable list with color, name, event count, visibility and a rename/delete menu. The lightweight visibility button saves immediately without a progress bar; hidden rows also say they are hidden. Name and color changes save only on confirmation, and deleting still uses the dangerous-action confirmation. The resource-header plus opens the name form directly. Manager child tasks preserve the parent position and scroll; saving or a child task blocks parent dismissal. Import/export closes the manager and waits for its exit before entering the existing transfer page. No overall Save button or placeholder category is introduced.

Settings opens a grouped overview on every window size, not a complete form flattened onto the first page. The overview and wide index prioritize enabled student/general workflows, then notifications, appearance/language, workspace management, data/privacy and About; initial index selection follows the first available group. Settings use connected neutral row surfaces, not nested cards: a 2 dp seam, 24 dp outer corners, 4 dp inner corners, and no elevation. SurfaceContainerHighest in dark mode and SurfaceContainer in light mode separate controls from the page; icons and values use onSurfaceVariant, with accent reserved for headings and actual state. Titles use ordinary body weight; explanations sit beneath the title, while a current value is trailing or wraps below when it cannot fit. Selection menus share this row layout on phone and desktop. Their actual MenuAnchor wraps the current-value control, not the full row; intrinsic option widths are bounded by the safe viewport instead of stretching to the row width. The entire row remains pointer-activatable with one keyboard/semantics trigger, and focus/session/save protections remain in force. Only common theme controls and the notification master switch stay inline. Student grid and general calendar preferences (including custom column width), reminder defaults, workspace switches, privacy/clear-data and about details belong on their respective secondary pages. Import/export, backup, version check and those secondary destinations have explicit overview entries. Full app backup and restore has one entry in the overview; the data/privacy detail page contains only privacy policy and local data cleanup, never a duplicate backup launcher. Show the version under Check for updates, not again as the About entry's subtitle. Phone overview uses Material's large collapsing title inside its one CustomScrollView; its local app-bar theme must not inherit a compact title font. Pointer/wide layouts keep a compact, pinned, native-caption-safe toolbar with the existing continuous frame background. Wide navigation anchors the same groups and preserves overview scroll and nested route state across resize; detail pages avoid a duplicate back button beside the wide index. Appearance, calendar display and reminders reuse the same connected rows. Color palettes and outline summaries share the group surfaces, and informational notices stay on the page background. On phones the live appearance preview follows its controls; on wide windows it remains alongside them. Saving guards also block toolbar and system back at the nested navigator root. Display and interaction preferences belong in Settings, never in home toolbars or overflow menus. Theme targets never change active mode; an exact user seed remains stored, while small foreground accents may use a readable tone from its Material color family. Language selection always opens its searchable standalone page, preserving search on resize and guarding back during save. Period-time-set selection is a dialog from Settings and the student resource menu; its edit/create actions remain available. A confirmed selection saves once to the opening timetable before closing, retains the dialog on failure, and does not retarget a newly active timetable. Dangerous operations stay separate from ordinary data actions.

The About detail page owns the saved prerelease-update opt-in; it defaults off and does not add an inline switch to the overview. Its row explains stability tradeoffs. Switching channels clears the cached update badge, guards the save, and prevents stale in-flight results from prompting under another channel.

Course-specific system reminders live under More, without a notification-settings jump button. A collapsed summary reflects the draft; collapse does not change an override. Saving an invalid custom minute value expands and focuses the error instead of silently inheriting the default.

## Date navigation and picker
One custom calendar serves navigation and business forms. The general calendar has a natural Monday–Sunday Week preset and a freely chosen inclusive Custom range of 1–14 days. Two clicks (or two validated date inputs) apply a complete range, including weekends; reversing clicks sorts endpoints, while invalid or overlong ranges retain the start for correction. A manually selected seven-day range remains Custom. Month navigation selects a month and clamps the focal day. Sidebar month browsing is transient and never navigates the main calendar. Date-format preferences apply equally to desktop and touch toolbars.

Desktop pickers remain anchored to their trigger and wide-tablet pickers remain centered. Compact touch windows choose presentation by task: semester-week jumps use a bounded 320 dp anchored popover with a transparent modal barrier; business single-day selection (day + confirm + no range interaction) uses a centered 360 dp calendar; all time-of-day choices use centered 320 dp cards. Floating card widths clamp to safe bounds and may grow with large text. Week popovers prefer below, then above, then a centered fallback when the anchor cannot be used. Centered phone cards use 24 dp corners and a 24% black scrim; week popovers use 16 dp corners. The shared host defaults to bottom-sheet presentation, so home date/month/week navigation and custom-range dragging retain their existing behavior. Course/event details and editors still use their existing mobile bottom routes.

Keep one picker route and draft across resize, IME and input-mode changes. Floating tasks do not paint a navigation-bar strip or duplicate insets. Short-window bodies scroll before the action footer; an exceptionally short window may scroll the complete task. Single-day cards have one month/year header with previous/next controls, a 4–6-row calendar, input/Today actions leading and cancel/confirm trailing; no redundant close button or date summary. Today updates the draft, not storage. Footer groups wrap before text is squeezed. Buttons and week cells keep 48 dp touch targets; a seven-column calendar at 320 dp cannot have 48 dp-wide cells, so reduce horizontal margins first, keep at least 48 dp row height and never shrink date text to claim compliance. Day/month navigation commits on activation; custom navigation commits once both endpoints are valid and persistence succeeds. Forms confirm into the existing draft and retain cancel. Date bounds, recurrence validation and workspace availability remain owned by the calling workflow.

Time tasks retain two independent, genuinely looping hour/minute wheels. Compact cards default to three visible rows with one shared center band and no column frames or duplicate input fields; a localized keyboard/wheel action switches between wheels and direct input. Wide-tablet/desktop tasks retain five rows and simultaneous direct input. Modes share one time draft. Wheel movement selects only after settling; confirmation alone returns a minute-precise value, while cancellation stays available. Hours and minutes wrap without carry or changing AM/PM. Switching mode and confirming are blocked during movement or invalid input; invalid text stays visible instead of reverting silently. Mouse wheel, trackpad, dragging, tapping, keyboard stepping and finite accessibility increment/decrement values remain supported. Wide input still chooses the nearest wheel position and interrupts old inertia. Stale callbacks cannot overwrite newer text; programmatic positioning respects reduced motion. Course/period workflows retain 24-hour input, while events follow their existing system/locale format.

Week navigation activates one date without implicitly creating a custom range. The sidebar separates single-click navigation from deliberate mouse range dragging; explicit range tasks support two activations, hover/keyboard previews and the existing two-date input mode. The calendar highlight carries normal selection feedback: do not add persistent instructions, duplicate range summaries or extra endpoint/restart buttons. Open a range task from the existing Custom view menu or range title; errors and retry use the existing header row without moving date cells. Mouse release commits only a valid, in-grid selection, while pointer cancellation and out-of-grid release discard the drag. Range preview notifications remain local to the picker; they do not persist or rebuild the event canvas.

GeneralDateRange owns civil dates, inclusive length and whole-range shifts; no fixed 24-hour arithmetic. Selected day and custom endpoints are separate. GeneralScheduleData.customDayMinWidth is nullable: null retains automatic sizing; manual values are 64–320 logical dp in 8 dp steps (initial 96 dp). Apply this uniform minimum only to an active Custom range, including a manually selected seven-day range. Columns fill surplus space or share one horizontal scroll offset across headers, all-day lanes and timed hit targets. Preserve fractional leading-date and time anchors when metrics change. Persist the optional preference in normal data/full backups without a schema-version bump; content-only calendar imports do not replace it. Forward/back and permitted paging gestures move by the range length. Today/external navigation retains a containing range or reanchors its unchanged length; near the upper bound the whole range shifts. Day/month/list visits retain the saved range. Week explicitly clears the active custom state; the current UI session can recall its last custom range, but restarting does not silently undo an explicit clear.

GeneralScheduleData schema v5 persists optional canonical start/end dates; root schema stays v3. Older data without a range uses the Week preset. Invalid v5 ranges enter storage recovery, and v4's strict event/recurrence validation is retained. Range/focus changes publish together only after a successful write, using the provider transaction barrier and repository write queue. Pure viewport navigation does not acquire the notification runtime lock; workspace-availability mutations still do. Preserve deferred-write ordering, failed-save rollback and data-session checks. Complete data replacement invalidates old picker sessions even if the workspace stays enabled. Ordinary category/ICS imports retain navigation; full backups include it.

Header, all-day lanes, event query and read-only assistant context share the actual range. Custom columns use the existing minimum width and horizontal scrolling, never hide weekends or compress text. Month/time rails and all-day controls stay pinned at the leading edge, including RTL layouts. Touch date controls show the custom day count directly, not only in a tooltip. Docking budgets grow only up to the existing seven-day budget. A bounded/rebased range pager avoids giant scroll extents at fractional window widths; grid horizontal scrolling disables range swipes. A home-owned viewport session retains horizontal position and visible time (in minutes) across range paging and view roundtrips. Explicit date navigation has a separate, non-persisted focus revision so Today and external jumps reveal the target column; ordinary range paging does not reset scroll. Entering custom with an outside saved focus uses the same length-preserving reanchor rule. If a saved range has no focus field, its start is the default, rather than silently moving that range to today.

A narrow desktop calendar budgets only the width left after native-caption clearance. Prioritize a measured full/short date or week label, then previous/next and Today when complete controls fit; an extreme large-text fallback uses a labelled date icon, never shrunken or half-clipped text. More retains the displaced navigation, view, resource, add, reminder, settings and workspace actions, independently of mobile hidden preferences. The menu scrolls below native caption controls and retires only its own route on window/font changes; editor and picker drafts are not dismissed. Category name forms opt into anchored, transparent-modal presentation through the ordinary dialog host. ## Shared task infrastructure

`SkedTaskSession` captures the opening workspace, data session and optional target/parent/owner route; invalidation is irreversible. `SkedTaskRouteGuard` retires only its own route. Desktop and touch adaptive pickers both observe parent-route retirement and discard stale results; waiting for reverse-animation completion remains opt-in. `completeSkedTaskRoute` completes the owned task rather than blindly popping a newer modal. User exits still obey draft and busy guards.

`SkedTaskSubmissionController` supplies one in-flight mutation gate and workspace-exit protection; callers freeze inputs and retain their own draft, validation and feedback UI. Category mutations, theme colors and period-set writes share this mechanism without changing persistence or backup formats. `SkedColorDraft` preserves raw theme slots independently of preview RGB. Hex accepts exactly six RGB digits with optional leading # and surrounding whitespace. Invalid input disables submission; reselecting the current color mode must not reset validity, while actual mode changes synchronize the input and draft.

`SkedPanelHeader` only composes title, actions, close and drag areas; `SkedFloatingPositionController` only stores session-local geometry. Hosts still own positioning constraints, focus, modality and close policies. Independent details never acquire modal-form dismissal behavior through this reuse. See [the floating-panel specification and verification record](docs/DESKTOP_FLOATING_PANELS.md).

## In-app reminder summary preview
The general reminder summary is distinct from the editor's reminder picker and from OS notification delivery. Group in-progress first (soonest end), upcoming second (soonest start), ended last (most recent end); break time ties by title and occurrence key. Ended is a temporal status, not an incomplete-task alarm. Use readable theme status accents, primary titles, secondary local time ranges and explicit all-day labels rather than midnight timestamps; do not rely on color alone.

The app shell owns one runtime-only startup attempt. Only the initially visible, interactive desktop general workspace with reminder items may show it; skip empty, touch, inactive or busy startup contexts instead of switching workspaces or replaying it later. The automatic view retires after ten seconds, pauses its remaining time while hovered/backgrounded, and becomes untimed after pointer/scroll/keyboard interaction. Manual activation is always untimed and must not stack duplicate lists. Expiration must target only its own current route with an active owner, never a newer editor/dialog. Closing a preview never acknowledges reminders or changes persisted settings.

Desktop reminder and day-agenda list details have hidden, preview and independent states in one workspace-owned root OverlayPortal. A 300 ms mouse-hover preview has no close button, does not request focus and cannot be dragged; the source row, narrow crossing corridor and preview share a 200 ms leave delay. Click/keyboard/semantics activation or “Open independently” converts the same content in place without resetting scroll. The independent window has its own X and draggable title. Outside clicks, leaving the source, and closing/reopening the reminder list do not close it. There is no independent-detail background shield: the list and calendar keep their own interaction/dismissal rules. The normal event outside-dismiss preference does not apply to explicitly independent windows. One reminder detail per workspace; only explicit row activation switches its event, preserving its independent position and clearing new-event scroll/errors. Hover cannot retarget it.

Escape belongs to the focused window (with root child confirmations above both), not to an unconditional secondary-first stack. A list-owned Escape or X does not close independent details. Only transient previews use the unregisterable workspace priority-dismiss hook. Preview actions first become independent, then use existing busy/child safeguards; a rejected detail close never affects another window. Async completion checks event/session revision, data and workspace ownership and never blindly pops a Navigator. List loss, scrolling, anchor invalidation and backgrounding retire previews; data/workspace invalidation or event deletion retire independent details too. Secondary hover pauses startup auto-dismiss, explicit independence/actions cancel it. Touch and other calendar entry points retain their existing task stack.

Independent reminder details must resolve the current occurrence on refresh and immediately before each command, including after child confirmation; retaining the list's snapshot can overwrite newer fields or recurrence exceptions. Only an owned in-flight deletion defers occurrence-disappearance retirement until persistence settles; data/workspace invalidation always wins. Reject editing before promotion/dismissal if another full editor owns the workspace. Freeze the independent reading-height budget as well as its origin so closing the source list does not resize or jump long content.

The same workspace-owned detail host serves desktop day-agenda floating lists, fixed supporting agendas and month agenda lists. Source-local row keys, hover/scroll state and visible viewport bounds prevent simultaneous lists or hidden supporting panes from stealing an anchor. Only the current source scroll/hide/date change retires a transient preview. Explicit activation of the same occurrence from another source preserves the independent element, reading height and scroll. Agenda promotion adds neither a new route nor an automatic startup lifetime; touch and other calendar entry points remain unchanged. Track the latest activated entry separately from the preserved content session so action retries and cancelled confirmations restore the correct row focus. Cancel startup timing only through the current source. Agenda date changes invalidate only that source’s transient hover state (including multi-day rows that retain their occurrence key), never an independent detail or another list’s open/exit timer.

## Notification registration and recovery
Notification delivery is owned by native alarms/toasts, not foreground timers. The disappearance of a pending request is not evidence of a missed delivery. Keep a runtime-only, generation-scoped registration journal keyed by logical reminder and original UTC fire instant. Claim durably before the platform call; record acceptance afterward. An ambiguous call suppresses replay, while a proven pre-submission rejection can retry. Future missing alarms can still be repaired before their intended instant. Copy/locale changes do not create a new delivery identity, and explicit snooze actions use durable per-card receipts with a fixed new fire time.

Retain the one-minute late-recovery window and a five-second first catch-up delay, but only for identities known not to have been submitted. Establish the history boundary even while notifications are disabled; an upgrade’s unknown past is not replayed. Non-destructive runtime cleanup and ordinary cancellation retain evidence until two days after the later original/scheduled instant; data clear uses the existing generation fence. Windows pending metadata requires a real native pending ID; historical ownership alone is not pending work. Remove every duplicate copy of a proven-owned ID before replacing it and fail without appending if cleanup cannot make progress. Never claim OS display from scheduling success or an empty unpackaged-Windows active list. See the notification deduplication and Android device acceptance records in docs.

Runtime-store mutations acquire the cross-engine notification lock before reserving their instance queue. The queue still serializes concurrent work in a reentrant lock zone. A mutation must use non-enqueuing fenced reads and combine stale-record cleanup with its own write, never await cleanup queued behind itself. Keep durable registration and generation checks intact instead of using a timeout to report a pending operation as successful.

## Desktop course and event editors
Overlay and automatic-overlay editors are transparent modal floating tasks, anchored next to the activating button or calendar cell. Prefer 600 dp width (resizable 320–680), cap height at 720 dp and available space, keep a single draggable title, a scrolling body, and reachable Cancel/Save actions. A manual title drag detaches the position and keeps this opening floating; reopening follows the saved presentation setting. Side-by-side editors remain docked and reuse the same form without remounting routes or draft state.

Floating editors block background navigation, calendar input and assistant controls; independent event details are offstage, not destroyed. Tab stays within the task, including its keyboard resize handle. Outside dismissal honors the existing setting and draft guard, child tasks own their dismissal, and saves complete only their owned route. Docked editors retain background and assistant interactions. Touch layouts, dangerous confirmations and persisted data formats are unchanged.

Desktop editor bodies are dedicated compositions, not mobile form sections restyled in a floating shell. Use a primary title input, adjacent metadata, aligned label/control rows and thin group separators. Course start/end values form one range; event start/end rows align their date/time controls and put the all-day switch in the time section header. Secondary fields and course reminder overrides use the same external-label treatment. Value controls remain at least 36 dp tall. Width changes reflow stable field elements instead of replacing inputs or resetting selection.
