# Sked adaptive workbench design

## Authority
Material 3 Expressive, semantic ColorScheme roles and exact saved user colors remain authoritative. Reference screenshots inform hierarchy and continuity, not imitation. No new UI, routing or state framework.

## Composition
Student timetables lead with the complete time canvas. General day/week views lead with the calendar; selected-day agenda is opt-in. Month uses calendar + selected-day agenda when space permits. List uses list/detail without a duplicated agenda. A single enabled workspace removes mode chrome, not settings access.

## Continuous surfaces
Use two continuous structural roles, resolved through SkedSurface: content uses ColorScheme.surface; navigation, the complete toolbar and docked panes use surfaceContainerLow. Caption clearance, pane headers, nested routes, safe areas and footers must inherit the same role instead of exposing a different background. A docked editor inherits frame; the same editor presented independently inherits content without recreating its draft. Independent dialogs/pickers explicitly reset the role. Structural surfaces have no tint or scrolled-under recoloring; retain modal scrims and shadows. Separate ordinary groups with spacing and hairlines, not extra filled cards. Controls, selected/hovered/error states and saved event colors remain semantic and unchanged. Desktop controls are compact; touch targets remain at least 48 dp.

## Task budgets
Window classes remain 600/840/1200 dp, not device classifications. WorkbenchLayoutPolicy owns actual pane decisions. Resources: 224 dp, compact: 56 pointer / 80 touch. Detail: 360, assistant: 400, base canvas: 600, seven-day calendar docking budget: 800. Forms use 224 navigation + 520 content, so an 800 dp portrait tablet can show settings categories and content even when its calendar stays a single task. Scale budgets with text; never shrink text to preserve a column.

Collapse resource navigation before overlaying detail, then overlay the independent assistant. Preserve intended widths and open states through automatic fallback. Only the top visible overlay receives focus. Calendar horizontal scrolling and week paging must not compete.

## Windows chrome
One integrated application/window row, not a second title bar. Native Win32 retains resize, move, maximize, system menu, close and HTMAXBUTTON snap semantics. Application controls must win hit tests over drag regions. Close awaits draft guards and pending saves. Android keeps its own safe areas, Back and IME behavior, never Windows caption buttons.

## Stable tasks and AI preview
Editors own drafts independently of their presentation. Ordinary workspace switching, settings visits and rotation do not discard drafts. Full data replacement must retire old editor sessions even if their workspace remains enabled. AssistantPaneController is independent from the detail navigator. The assistant is off by default. DeveloperUiPreferences stores its local show/hide choice outside AppData and backups; a saved choice overrides SKED_AI_LAYOUT_PREVIEW. A preview only displays read-only context and an unsent session draft, never fake AI actions.

## Settings and workflows
Six direct categories use the settings catalogue; there is no settings-center search. Language search remains local to the language list. Workflow preferences belong in their workspace. Explicit theme targets never change active mode. Period times are ordered rows; import source, parsing state and validation form one stable task. Dangerous operations are separate from ordinary data actions.

## Date navigation and picker
One custom calendar serves navigation and business forms. The general calendar has a natural Monday–Sunday Week preset and a freely chosen inclusive Custom range of 1–14 days. Two clicks (or two validated date inputs) apply a complete range, including weekends; reversing clicks sorts endpoints, while invalid or overlong ranges retain the start for correction. A manually selected seven-day range remains Custom. Month navigation selects a month and clamps the focal day. Sidebar month browsing is transient and never navigates the main calendar. Date-format preferences apply equally to desktop and touch toolbars.

Desktop pickers remain anchored to their trigger and wide-tablet pickers remain centered. Compact touch windows choose presentation by task: semester-week jumps use a bounded 320 dp anchored popover with a transparent modal barrier; business single-day selection (day + confirm + no range interaction) uses a centered 360 dp calendar; all time-of-day choices use centered 320 dp cards. Floating card widths clamp to safe bounds and may grow with large text. Week popovers prefer below, then above, then a centered fallback when the anchor cannot be used. Centered phone cards use 24 dp corners and a 24% black scrim; week popovers use 16 dp corners. The shared host defaults to bottom-sheet presentation, so home date/month/week navigation and custom-range dragging retain their existing behavior. Course/event details and editors still use their existing mobile bottom routes.

Keep one picker route and draft across resize, IME and input-mode changes. Floating tasks do not paint a navigation-bar strip or duplicate insets. Short-window bodies scroll before the action footer; an exceptionally short window may scroll the complete task. Single-day cards have one month/year header with previous/next controls, a 4–6-row calendar, input/Today actions leading and cancel/confirm trailing; no redundant close button or date summary. Today updates the draft, not storage. Footer groups wrap before text is squeezed. Buttons and week cells keep 48 dp touch targets; a seven-column calendar at 320 dp cannot have 48 dp-wide cells, so reduce horizontal margins first, keep at least 48 dp row height and never shrink date text to claim compliance. Day/month navigation commits on activation; custom navigation commits once both endpoints are valid and persistence succeeds. Forms confirm into the existing draft and retain cancel. Date bounds, recurrence validation and workspace availability remain owned by the calling workflow.

Time tasks retain two independent, genuinely looping hour/minute wheels. Compact cards default to three visible rows with one shared center band and no column frames or duplicate input fields; a localized keyboard/wheel action switches between wheels and direct input. Wide-tablet/desktop tasks retain five rows and simultaneous direct input. Modes share one time draft. Wheel movement selects only after settling; confirmation alone returns a minute-precise value, while cancellation stays available. Hours and minutes wrap without carry or changing AM/PM. Switching mode and confirming are blocked during movement or invalid input; invalid text stays visible instead of reverting silently. Mouse wheel, trackpad, dragging, tapping, keyboard stepping and finite accessibility increment/decrement values remain supported. Wide input still chooses the nearest wheel position and interrupts old inertia. Stale callbacks cannot overwrite newer text; programmatic positioning respects reduced motion. Course/period workflows retain 24-hour input, while events follow their existing system/locale format.

Week navigation activates one date without implicitly creating a custom range. The sidebar separates single-click navigation from deliberate mouse range dragging; explicit range tasks support two activations, hover/keyboard previews and the existing two-date input mode. The calendar highlight carries normal selection feedback: do not add persistent instructions, duplicate range summaries or extra endpoint/restart buttons. Open a range task from the existing Custom view menu or range title; errors and retry use the existing header row without moving date cells. Mouse release commits only a valid, in-grid selection, while pointer cancellation and out-of-grid release discard the drag. Range preview notifications remain local to the picker; they do not persist or rebuild the event canvas.

GeneralDateRange owns civil dates, inclusive length and whole-range shifts; no fixed 24-hour arithmetic. Selected day and custom endpoints are separate. Forward/back and permitted paging gestures move by the range length. Today/external navigation retains a containing range or reanchors its unchanged length; near the upper bound the whole range shifts. Day/month/list visits retain the saved range. Week explicitly clears the active custom state; the current UI session can recall its last custom range, but restarting does not silently undo an explicit clear.

GeneralScheduleData schema v5 persists optional canonical start/end dates; root schema stays v3. Older data without a range uses the Week preset. Invalid v5 ranges enter storage recovery, and v4's strict event/recurrence validation is retained. Range/focus changes publish together only after a successful write, using the existing serialization barrier and runtime lock. Complete data replacement invalidates old picker sessions even if the workspace stays enabled. Ordinary category/ICS imports retain navigation; full backups include it.

Header, all-day lanes, event query and read-only assistant context share the actual range. Custom columns use the existing minimum width and horizontal scrolling, never hide weekends or compress text. Month/time rails and all-day controls stay pinned at the leading edge, including RTL layouts. Touch date controls show the custom day count directly, not only in a tooltip. Docking budgets grow only up to the existing seven-day budget. A bounded/rebased range pager avoids giant scroll extents at fractional window widths; grid horizontal scrolling disables range swipes. A home-owned viewport session retains horizontal position and visible time (in minutes) across range paging and view roundtrips. Explicit date navigation has a separate, non-persisted focus revision so Today and external jumps reveal the target column; ordinary range paging does not reset scroll. Entering custom with an outside saved focus uses the same length-preserving reanchor rule. If a saved range has no focus field, its start is the default, rather than silently moving that range to today.

## Evidence
Windows full-window captures validate native chrome; Flutter render captures validate logical layout only. Neither certifies Android phone/tablet hardware. Inspect desktop and tablet-oriented layouts together, fix a consolidated batch, then confirm.

## Desktop/tablet revision (2026-09-09)
WorkbenchChromeMetrics owns desktop density: one 48 dp application/caption row at normal text, 32–36 dp commands, 46 dp caption buttons. Growing text grows the shared row. Win32 receives the measured maximize rectangle over configureChrome; do not duplicate these dimensions in C++. Android retains 48 dp touch targets.

Desktop commands are independent of mobile toolbar ordering/hidden preferences. Resource headers own add, manage, import and export. Calendar rows use colored markers and a light visibility state, not checkbox tiles. Settings live at the navigation foot; only missing navigation produces a fallback. Never duplicate workspace switching inside management/preferences menus.

Timed events first receive overlap columns; only actual day width and text size determine overflow. A small count affordance never takes a peer event column. All-day content starts with two lanes (28 dp desktop, 48 dp touch), with bounded scrolling on expansion. Preserve real event durations and all configured date/time space. Reminder status lives behind the compact toolbar action.

Appearance uses aligned labels/dropdowns with local preview, not three stretched segmented controls. Course reminders are system reminders with inherit/off/custom overrides and explicit default/permission conditions. Existing general in-app reminder behavior is separate.

## Semester week navigation
The timetable week title opens a compact, bounded numeric grid through the shared picker host. Desktop tasks anchor to the title (or the persistent More control); compact touch tasks anchor near the same trigger with a transparent modal barrier, while wide tablets retain centered presentation. Eighteen weeks fit in four five-column rows at normal desktop scale; reflow with text size, keep at least 36 dp pointer / 48 dp touch targets, cap the grid at six visible rows and reveal the selected week on open. Ordinary cells have no fill or border; use only selection/focus feedback and a dot for the actual in-semester current week, never the clamped boundary week outside the semester. Full Monday-to-Sunday dates belong in tooltips and accessibility values, not a visible summary. Keyboard movement and scrolling preview locally; activation navigates once and dismisses, while closing cancels. Week numbers do not loop, and navigation does not write storage. A caller-supplied validity predicate retires a picker on timetable/config/data/workspace or external-navigation changes; check again through the existing navigation animation before applying its result. Preserve the current-day shortcut, More entry and trigger focus; independent date/time tasks retain their existing behavior.
