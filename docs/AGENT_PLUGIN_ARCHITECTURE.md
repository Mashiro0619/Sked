# Agent 插件架构与上线目标

状态：设计已确定，实现待开始；重构基线为 106dc96264634b110b4afc346d5f140b46da4097。本文定义下一阶段目标、接口、实施顺序与原子提交边界；当前运行行为见[运行说明](AGENT_RUNTIME.md)，已有原生实现见[Rust 迁移](AGENT_RUST_MIGRATION.md)。

## 产品目标

Sked 提供一个通用、可扩展的 Agent：它能理解用户目标，自主组合应用业务、设备文件、网页、文档与执行工具，完成跨功能任务；缺少信息时询问，遇到失败时依据实际结果继续处理，并交付真实保存的结果。用户继续使用清晰统一的 Sked 界面，能力通过插件持续扩展。

以下三个例子是首发能力的最低验收标准。产品的能力边界由可组合的服务和工具决定，不能限定为这三类任务：

1. 读取考试安排，澄清缺失信息，结合已有课程和日程制定复习计划，并实际保存日程。
2. 读取学校近期公开通知，继续访问相关链接及附件，整理与用户有关的事项，保留来源和日期，按请求加入日程。
3. 读取文件夹资料，生成笔记，保存到用户指定的位置，并给出文字行动清单。待办业务功能尚未开发，行动清单保持为交付内容。

实现围绕通用能力展开。模型通过工具和 Skills 组合完成任务，Agent 循环不包含考试、学校通知或资料笔记的专用分支。相同能力应能继续处理文件内容修改、表格整理、资料比较等其他请求。

## 学习标准与技术路线

主要学习标准为 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness/tree/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159)，本次研究固定在上述源码版本。采用其服务定义、Provider、插件实例、持续依赖、资源归属、Skills 与产品装配思路；Sked 使用自己的插件接口，复用适用的技能资源与实现经验。

技术栈采用 Flutter 界面、Rust 共享核心和可插拔执行环境。Windows、Android 共用主要 Agent 逻辑，平台适配集中在系统权限、资源访问、解释器载体和后台生命周期。

首发先完成 Agent 内部插件化。后续课表、日程、页面和其他功能沿用同一套服务、贡献与生命周期契约逐步接入。内置插件随应用编译发布，自定义 Skills 继续通过已有入口管理；可安装代码插件和插件市场属于后续扩展。

DSH 的普通文件在模型适配前被投影为执行环境中的文件路径，由 Agent 通过工具读取；Office 工作流使用 Skills、Python 文档库以及按需调用的 LibreOffice。Sked 同样提供真实可用的文件、执行环境和文档库，同时保留当前模型原生文件输入能力。参考源码：[文件投影](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/llm/llm/src/content.ts)、[Office 技能](https://github.com/deepseek-ai/deepseek-harness/tree/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/skill/skill-office)。

## 插件契约与所有权

Rust 统一管理插件装配、服务依赖、实例和退出过程。Dart 提供 Flutter 界面、现有业务服务及系统接口，跨语言调用继续使用类型化 FRB 命令与事件。

| 公共契约 | 需要表达的语义 |
| --- | --- |
| PluginDescriptor / PluginInstance | 插件身份、契约版本、配置、提供的服务、依赖和实例状态 |
| ServiceDefinition / Provider / ServiceLease | 消费者依赖接口；租约绑定具体提供者及代次，在途调用保持原实现 |
| EffectScope | 工具、监听、任务和界面贡献归属调用插件，撤销和异步收尾有明确完成信号 |
| AgentProfile | 声明默认插件组合、平台 Provider 和启动所需能力 |
| ResourceRef / SourceSnapshot | 表达系统资源、实际读取版本、来源、摘要和持久内容引用 |
| ToolExecutionResult | 分别承载结构化结果、模型内容、资源引用与界面信息 |
| ExecutionSpec / ExecutionReceipt | 固定代码与环境，记录接纳、启动、取消、结束及可观测产物 |

模型、Agent 循环、工具目录与执行器、权限审批、存储恢复、上下文压缩、知识、附件和历史都作为服务插件。稳定的是契约、生命周期和产品装配要求。当前 Rig、JSONL / SQLite、Dart 业务保存与系统凭据服务成为默认 Provider。

插件退出顺序为：停止接纳新工作，取消可取消任务，完成已接纳保存并持久记录结果，释放消费者，最后释放 Provider。装配失败撤回本次产生的注册和资源。退出插件不自动删除已经保存的用户内容。

默认持久化继续使用每会话追加式 JSONL、可重建 SQLite 索引、knowledge.sqlite 和附件文件。纯 Provider 迁移保持原保存行为；新增内容引用在功能提交中同时接通持久化、恢复和回收。Agent 开发数据允许按既有决定重建，业务数据、连接、凭据与用户设置保留。

迁移保留多会话、排队与立即补充、问答计划、三种权限、知识、历史、附件、恢复及自动标题。输入区操作组在窄屏下仍保持一行，正文保持多行输入；界面保留固定模型浮层、允许／拒绝审批和现有活动展示。工具结果、设置与详情通过可撤销的界面贡献接口接入。

普通运行继续不设置累计 Token、模型轮数、工具次数或普通任务时限配额。用量记录与执行控制分开，按用户配置和模型实际能力管理上下文；文件分页与流式处理不构成任务总量限制。

## 默认能力

### 设备文件与网页

文件服务提供目录浏览、文件和文本搜索、读取、新建、修改及保存。访问按操作系统实际允许的范围，不另加 Sked 工作目录白名单。Windows 使用当前用户权限；Android 11 及以上统一申请所有文件访问，较旧版本使用相应存储权限，保留系统文件选择器入口。其他应用私有目录继续遵循系统隔离。

目录与文本按需分页，二进制流式处理。修改已有文件前核对读取版本，版本变化时返回冲突和当前状态。系统资源使用真实路径、URI 或句柄语义；选择器取得的资源不强行伪装成普通文件路径。权限未授予或撤销时，返回可理解的原因及可用入口。

网页服务提供 HTTP 抓取、正文与链接提取、继续读取链接和附件下载。网页附件进入同一文件处理链。来源记录区分原始地址、最终地址、抓取时间和网站实际提供的发布日期。首发聚焦公开网页；登录内容沿用用户选取后交给 Agent 的入口，全网搜索后续接入。

### 执行环境、Skills 与 Office

执行服务统一提供启动、输出、进度、取消、结束状态和产物登记。Windows 随包提供 CPython，以独立进程执行；Android 使用 Chaquopy，在专用 Service 进程执行。进程隔离用于故障隔离和终止任务，权限范围按运行环境的真实能力表达。

首版采用 CPython 3.11，保留当前 Android arm64、armv7 与 x86_64 目标；Android 采用 Chaquopy 17.2，其最低 API 和 AGP 支持范围与当前工程匹配。依赖在构建时锁版并随包提供，解释器按需启动。依据：[Chaquopy 平台与构建要求](https://chaquo.com/chaquopy/doc/current/android.html)。

Office 插件复用 python-docx、openpyxl、python-pptx 及所需依赖，支持 DOCX、XLSX、PPTX 的内容读取、创建和常规修改。共享 Skills 按需加载，指导 Agent 使用库、检查结果和交付文件。Office 排版渲染、公式重算和 PDF 导出作为后续独立 Provider；写入公式与计算公式结果分别表达。

执行权限沿用三种模式：

- 计划模式允许受控读取，任意脚本只形成代码与执行预览。
- 确认模式的审批绑定实际代码、参数、执行环境和权限修订；材料变化后重新取得许可。
- 完全权限通过相同接纳校验后，在系统许可范围内执行。

Office 只读检查使用固定入口和结构化参数，入口不接受任意代码、动态模块或命令。通用脚本通过执行许可启动，Skill 或模型声明不能将其改成只读工具。准备执行阶段冻结材料，不提前运行脚本或安装依赖。

执行回执区分未启动、已启动、正常结束、取消和结果未知，并关联输出及可核对的文件效果。失败退出不等于文件没有发生变化。重开后核对原执行记录，不自动重跑结果未知的脚本；通用脚本不承诺自动撤销。

### 模型内容、来源与产物

文本和 Office 提取结果以真实正文进入上下文。图片以及当前模型支持直接接收的 PDF、办公文件通过实际内容块发送。文件路径只表达资源位置，读取成功与内容进入模型请求分别记录。

工具读取的内容保存为不可变快照，绑定来源、摘要与原工具调用。完整工具结果组结束后，将附加内容加入同一次运行，不产生虚假的用户消息。持久快照和当次模型协议编码分别管理，避免把 Base64 写入会话日志。

内容桥接同时覆盖历史重建、压缩、重生成、备份和附件回收。重开使用原快照，重新读取外部资源才产生新版本。压缩按真实用户轮次和完整工具组划界，保留可重新读取的内容引用。

原生文件输入需修正当前 Chat Completions 的 PDF 引用在 Rig 编码前后可能丢失的问题；发送前核对预期媒体块仍在请求中，全部私有引用已被真实内容替换。模型或协议不支持时，选择已提供的内容处理能力或说明具体缺口。

交付统一展示实际保存位置、可打开的文件、来源和业务回执。日程使用现有业务事务保存；笔记和文档使用文件服务保存。Agent 完成状态依据真实结果，不以生成了文字或脚本代替交付。

## 桌面基础交互

通用能力上线同时补齐整个桌面应用的基本操作。具体缺口、行为和独立提交顺序见[桌面基础交互计划](DESKTOP_INTERACTION_PLAN.md)：优先让会话、课程、日程和资源支持右键上下文操作，接通区域搜索、当前编辑任务保存等快捷键，再接入文件拖入、截图粘贴及保存结果的系统打开与定位。

桌面交互作为并行工作推进，不等待 Agent 插件重构完成。菜单、快捷键与工具栏复用同一对象动作及既有业务规则，后续与插件界面贡献对接。三个例子仍是通用 Agent 的最低能力验收；桌面交互按独立的实际操作标准验收。

提交约束：

- 每笔只解决一个问题，包含相关实现、必要回归材料与受影响的行为说明。纯装配重构和新增行为分别提交。
- FRB 双端类型与生成代码同笔；新增持久引用与恢复、回收逻辑同笔；审批预览与实际接纳边界同笔；平台实现与正式调用入口同笔。
- 每笔都应形成完整的可编译、可验证、可回退边界。当前测试与构建暂停，记录实际审查范围；暂停期间不得将这些状态标记为通过。
- 提交前检查暂存差异，仅暂存当前条目。使用中文单行消息、SSH 签名并执行 git verify-commit。保留他人的未提交修改。
- 在 main 开发；开发脚本、日志、截图及临时测试工件统一放 F 盘。应用运行时文件按设备自身的私有存储和临时目录管理。

## 验收与发布

测试、构建、真实模型调用及性能采样继续暂停。下面是恢复后的验收标准，验证提交随各自独立问题安排，不以此提前启动执行。

1. Windows、Android 至少都能完成本文的三个例子，日程和文件实际保存且可以重新打开。
2. 使用同一套工具完成不同于三个例子的任务，例如比较两份文档差异后更新指定文件，或整理工作簿数据并生成另一份结果；新增任务不要求修改 Agent 主循环。
3. Office 内容实际进入推理，图片和 PDF 的真实内容到达支持它们的模型。文件来源、快照和读取状态可追溯。
4. 权限拒绝或撤销、源文件被其他程序修改、网络失败及用户停止时，界面和回执准确表达已经完成与尚未完成的结果。
5. 重开后核对已有执行记录，保留已读快照，不重复保存日程或自动重跑结果未知的脚本。
6. 插件退出撤回其资源，既有会话、队列、历史、业务保存和恢复行为保持有效。
7. 桌面对象右键、键盘菜单、区域快捷键和文件交付符合[桌面交互计划](DESKTOP_INTERACTION_PLAN.md)；保留标准文本编辑、窗口操作和焦点行为。

Android 各分发渠道统一采用已确定的文件权限方案，Google Play 的相应权限审核列为发布条件。恢复验收后按源码版本、命令、平台和实际范围记录结果。
