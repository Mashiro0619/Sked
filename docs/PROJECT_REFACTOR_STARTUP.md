本轮继续补齐全项目重构的启动验收。既有工作区挂载和 `lifecycle.disk_load` 结果保留原边界，不能替代进程创建至首个就绪画面的冷启动时间。

## 通知运行时锁的隔离作用域

`AgendaRuntimeMutationLockScope` 接收明确的绝对锁文件路径。`withAgendaRuntimeMutationLockScope` 将它应用于当前调用及在其中注册的异步回调，通知协调器、通知服务与业务命令沿用原有锁入口。broker 身份由规范化路径确定；显式默认路径与未设置作用域的调用继续使用原 broker。

每份重入令牌绑定锁身份并在释放时失效，因此 A 内获取 B 仍会等待 B，A → B → A 可以复用仍持有的 A。新 broker isolate 显式接收路径与 namespace，业务工作 isolate 也必须自行安装传入的作用域。默认锁文件、消息协议、队列、超时和心跳算法保持不变。

路径规范化不解析符号链接、硬链接或 Windows 短路径别名；调用方需传递同一受检路径。文件访问失败时仍保留原有进程内队列回退，独立启动基准还需证明隔离目录和真实文件锁可用。

保留原有六项锁测试，新增八项作用域行为测试。锁、通知服务、协调器和后台对账的四个文件在 Windows 与 Linux 各通过 163 项。验证包括跨 isolate 串行、跨作用域独立执行、嵌套重入、失效令牌及默认兼容；两个作用域创建的文件经文件身份查询确认不同。测试使用独立临时根，未借用真实应用实例的通知锁。
