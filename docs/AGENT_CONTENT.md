# Agent 文件内容与上下文

工具可以分别返回结构化结果和实际模型内容。结构化结果记录来源、位置、版本和操作回执；正文与二进制通过独立的内容字段交给原生运行服务保存。会话日志保存内容引用，文件字节保存在附件目录。

## 读取与继续

`files.read` 默认按 UTF-8 文本分页读取，`offset` 和 `nextOffset` 使用字节偏移。每次返回的文本范围在完整字符边界结束；下一页继续使用返回的偏移。保存的是整份不可变文件，文本范围决定本轮提供给模型的正文。

图片、音频、PDF 及其他模型文件输入使用 `format: native`，发送完整文件，省略分页参数。文件名和媒体类型优先取读取时的系统元数据；普通路径可以按文件名推断类型，无法确定时由调用明确提供。媒体类型比较使用去除参数和首尾空白后的类型名，并忽略大小写；原来源版本保持读取时的证据。旧 `base64` 参数会提示改用 `native`。

内容保存成功后返回稳定的 `contentId`、名称、媒体类型、完整长度、SHA-256 和本次文本范围。`content.read` 通过当前会话及其历史版本的内容 ID 重新读取已保存附件，可以继续分页，也可以按当前模型协议读取完整原生媒体。外部文件后来发生变化，不会改变已有内容；重新调用 `files.read` 读取该资源会生成新快照。

## 保存与原工具归属

带工具调用的模型消息先持久保存，再派发所属工具。工具内容复制期间持有原快照读取租约，在同一个存储作业内核对字节、保存附件元数据、原工具消息内容引用和操作记录。附件回收不能插入复制与引用发布之间。

每项引用归属原 Tool 消息及调用，保存来源快照 ID、实际资源和版本；文本范围从整份已核验的附件中读取。同一内容 ID 在当前消息和历史版本中保持相同归属、附件、范围和来源，恢复时拒绝冲突绑定。后续模型事件合并这份已保存引用。内容字段无效、读取或内容保存失败时，单独记录内容交付失败及具体原因，已有业务与外部操作回执仍保留真实结果。

## 模型请求与压缩

每轮模型请求按本轮完整工具结果组定位附加内容，在组结束后编码真实正文和媒体。相同的协议调用 ID 在不同模型轮次出现时，仍按原消息及组内位置区分。协议所需的临时内容块不成为新的用户输入或持久用户消息。

进程在组内部分内容已保存后中断，恢复保留这些原工具消息及引用，依据持久结果补齐同组缺失项。没有完整结果的调用明确记录中断；已经接纳的业务操作继续核对原回执，恢复不自动重放调用。完整工具组修复后才能继续向模型提供其内容。

请求发送前核对媒体类型、附件身份、出现次数和实际字节。当前协议不支持的文件保留持久引用并说明内容处理缺口，模型可以继续使用已提供的提取工具。文本内容参与当前连接的凭据检查。

上下文估算和压缩包含本轮实际内容。压缩沿真实用户轮次与完整工具组切分，提交摘要时核对来源正文、内容引用和附件摘要。原消息及附件引用继续保存，重生成、历史重建和导入后的上下文使用各自有效的消息范围。

## 备份与回收

当前消息和历史版本的内容引用都参与附件保留。选择性备份将这些附件作为聊天依赖，按用户选择携带二进制；恢复复制附件身份时同时重绑当前和历史消息。新 Agent 归档使用版本 3，继续读取版本 2。未携带的文件在恢复后显示缺失。

系统文件服务独立管理 `files/snapshots`。活动访问、正在读取的内容、待写材料和写入日志中的原件及恢复证据保持引用；释放后回收不再需要的私有快照。会话附件由会话引用管理，两个目录分别回收。
