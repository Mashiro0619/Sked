## 统计方式

每个动作、每个进程先从其半开时间窗内的原始 engine FrameTiming 重新计算 nearest-rank P95/P99：排序后取 ceil(p × n) 对应帧。表格再取三个进程对应统计量的中位数。从不把六个进程或不同动作的帧合并后重新求分位数；P50、totalSpan、vsyncOverhead、min/max、MAD 及所有原始值仍保存在完整 JSON 中。

下文所有箭头均为“原版 → 当前版”。时间单位为 ms，RSS 为 MiB。max 默认表示三个进程各自最大帧的中位数；“最坏观测”另取三个进程最大值中的最大数。超预算比例计算 build > 4.166667 ms 或 raster > 4.166667 ms 的帧数 / 该动作采集帧数，其变化用百分点表示。它不是 FPS、屏幕呈现掉帧率或端到端输入延迟。

RSS 是整个进程的驻留内存。动作 RSS 增量先在各进程内计算结束值减起始值，再取三轮中位；它不是 Dart 分配量、动作内峰值，也不能据此判定泄漏。有正负号的 RSS 增量不计算百分比。三个重复只支持描述性比较，不构成显著性、因果关系或最坏情况上限。
