# Android 设备间迁移约定

Android 12 及以上、遵守系统备份规则的设备间迁移可以携带主应用数据中的课表、日程、节次时间集和普通设置。云备份和旧版系统整包备份继续关闭；这条路径不替代应用内由用户确认的 JSON 导入与完整备份恢复。

## 来源与迁移内容

系统只可读取 `files/Sked_device_transfer/Sked_data.json` 这一受控工件。原始 `files/Sked_data.json`、备份、临时快照和恢复日志都不直接列入迁移规则。BackupAgent 仅在明确的设备间传输标志下生成和输出工件，不向云备份输出文件。

工件从已提交的主文件另行生成，处理完整 JSON 后才可发送。过滤当前 `aiApiSettings.customApiKey`，以及旧版顶层和 `studentMode` 内的 `schoolImportParserSettings.customApiKey`，包括转义后的同名键及重复的字段。不能因为当前编码器不写密钥，就直接放行还没有完成安全迁移的旧原文件。其他普通内容保持其 JSON 含义；读取、过滤或写入失败时不发送旧工件，原存档及正常保存、备份轮换、密钥清理回滚语义保持原样。

安全存储、WebView Cookie 与站点会话、数据库、共享偏好中的通知注册与运行时凭据、设备绑定状态及缓存不进入迁移工件。规则使用单文件白名单，不依赖穷举这些文件的名称。

## 接收与恢复

接收端只处理本次恢复实际收到的受控工件，不把之前残留的文件当成本次输入。工件再次经过同一密钥过滤；缺失、无法完整读取、格式损坏或不支持的快照不触发默认数据覆盖。

只有尚无主存档、临时快照、备份或待恢复状态的目标才自动接纳。已有数据或恢复证据时保留它们，不以设备迁移覆盖。过滤后的完整候选先写入私有暂存文件，刷新后发布到正常的 `Sked_data.json.tmp`，再提升为主文件；在提升前中断时，由现有存储读取器按正常临时快照规则恢复。发布前的失败不留下可被当成成功恢复的半份快照，发布后的有效候选不被错误清理。应用启动后继续执行现有 schema 和模型校验，异常候选保留为恢复证据。

新设备使用本机安全存储，并重新读取实际通知与精确闹钟能力、重新建立本机通知计划；不采用来源设备的权限结论、注册凭据或系统排程缓存。需要 API 密钥或学校网页会话时，由用户在新设备重新提供。

## 验证边界

回归应覆盖三处旧密钥、转义与重复字段、普通内容保持、非法输入、工件失败清理、云传输拒绝、目标已有数据、暂存及提升失败、重复恢复与正常存储的衔接。平台检查器同时核对 BackupAgent、备份属性及精确的资源白名单，并对构建后的合并清单和资源执行检查。

这些检查证明源码规则、生成产物和受控文件行为。不同 Android 版本及厂商的真实换机流程、系统权限状态和最终提醒投递必须另行记录设备验收，不能用 JVM、文件夹具或 APK 构建成功替代。
