# 发布验收

本页维护各版本通用的验收要求。每次发布都应绑定最终提交和实际分发包记录结果，不能沿用旧版本的测试通过数、产物摘要或发布授权。

原始日志、截图、导出副本和一次性报告放在系统临时目录；现有本地发布清单与执行记录保持忽略。面向用户的变更说明保留在 `docs/releases/` 与 [CHANGELOG](../CHANGELOG.md)。

## 候选版本与产物

- 从 `pubspec.yaml` 读取版本和构建号；核对标签、发布正文、包内版本及最终 Git 提交一致。上传商店前核对后台已有版本，构建号不能在 Alpha、RC、正式版之间重置。
- GitHub 的预发布标记、Latest 设置与商店测试渠道分别确认。旧版本的发布授权和设置不能自动套用到新版本；客户端筛选规则见 [更新机制](updates.md)。
- 在最终提交上核对 [可靠性检查](RELIABILITY_BASELINE.md) 和对应 CI 结果。后续代码或构建配置变化后重新验证受影响的检查。
- Android 使用对应分发渠道的正式签名，核对应用 ID、证书摘要、包内版本与 ABI。分 ABI APK 与通用 APK 的原生版本号可能不同，升级验证应沿用相同包类型；CI 临时签名不能用于正式升级包。
- Windows 便携包包含完整 Release 运行目录、资源、运行库及 LICENSE / NOTICE，不只复制 exe，也不混入 Debug 内核。Store 与站外渠道分别构建，身份和版本映射见 [Microsoft Store 指南](microsoft-store.md)。
- 为最终分发文件生成 SHA-256 和产物清单，记录提交、工具链、版本、大小及签名；上传后核对远端附件与本地产物一致。不要通过悄悄替换同版本二进制修正发布问题。

## 设备与安装验收

以下是从旧版本记录中保留的验收缺口；整理文档时没有重新执行设备检查，也没有将其标记为通过。每次候选版本需分别记录结果与证据，不以发布成功替代验收。

| 范围 | 必须保留的检查 |
| --- | --- |
| Android 界面与系统交互 | 系统键盘、返回手势、安全区、横屏、大字号、编辑保存与恢复、厂商 WebView 与学校网页导入；使用真实设备，模拟窗口尺寸和键盘 inset 仅作补充 |
| Android 通知 | 权限、后台回收、重启、时区、稍后提醒、点击导航及厂商电池策略；按 [通知验收矩阵](ANDROID_NOTIFICATION_ACCEPTANCE.md) 逐项记录 |
| 同签名升级 | 使用真实旧版本、相同应用 ID、签名和渠道覆盖安装，核对课表、日程、设置、测试密钥、备份恢复与提醒；不以卸载重装替代 |
| Windows 用户环境 | 在干净环境检查启动、运行库与 WebView2、原生文件选择器、导入导出、通知激活和升级数据保留 |
| Windows 原生窗口与浮层 | 系统缩放、多显示器 DPI、标题栏、拖动、窗口边界、贴靠及代表性浮层操作；组件拖动断言不能替代原生鼠标验收，规则见 [桌面浮层](DESKTOP_FLOATING_PANELS.md) 和 [自适应工作区](ADAPTIVE_WORKSPACES.md) |
| 商店分发 | 对实际提交包核对身份、版本、签名要求、WACK／商店认证和可见范围；打开商店链接不表示更新已可下载 |
| 本地化 | 人工校对文案、日期／时间格式、截断和大字号布局；生成资源一致性与测试通过不能替代译文校对 |
| 其他平台 | 仅在需要分发时，使用对应平台检查构建和运行；Windows 本地结果不能证明 Apple／Linux 运行验收通过 |

## 执行记录

每次候选版本独立记录以下字段；未执行、失败、受阻和通过应明确区分。

| 字段 | 内容 |
| --- | --- |
| 候选身份 | 应用版本、构建号、Git SHA、分发渠道 |
| 包身份 | 文件名、SHA-256、签名证书摘要、包内版本 |
| 环境 | 日期、执行人、设备／系统／ROM、工具链 |
| 验证 | 场景、步骤、预期、实际结果、日志或截图位置 |
| 遗留项 | 未执行或受阻原因、影响范围、下一步所需环境 |

截图应注明真实平台与模拟条件。使用隔离测试数据，不记录实际凭据，不删除用户数据来消除失败。
