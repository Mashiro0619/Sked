# 对象选择备份与恢复

选择性备份使用版本化的对象清单和二进制归档。本文随归档、对象规划、恢复协调和正式入口的独立提交逐步补齐；交付进度见[实施计划](AGENT_IMPLEMENTATION_PLAN.md)。

## 归档格式与校验

ZIP v1 使用 `manifest.json`、逐对象 JSON 和按摘要标识的二进制文件。清单声明对象身份、依赖、路径、长度和 SHA-256；读取核对清单及文件，拒绝未声明项、重复项、错误摘要、循环依赖、链接、加密归档、路径越界及不支持的版本，不把 ZIP 路径解压到文件系统。

单份附件最多 32,000,000 字节，整个归档及解压内容各有 128 MiB 上限；单对象 16 MiB，清单 2 MiB，最多 2,048 个对象。聊天附件元数据与二进制分开表示，缺少文件内容时必须保留缺失事实，不能访问原设备路径。

对象通过类型与稳定 ID 定位，设备配置额外包含来源平台和分组。归档承载由各拥有者过滤的便携数据，密钥、Cookie、系统授权与运行许可不得作为导出内容。模型和编解码器不自行写入业务仓储，也不提供界面入口。

## 对象选择与依赖规划

同稳定 ID 的选中对象替换原位置，不存在则新增；同名不合并，空分组不清空本机整类数据。选中父对象的子集合可以恢复为空，未选对象保留。

课表与节次时间集、聊天与附件分别保存明确依赖。必要依赖与本机内容相同时复用，冲突时只复制该依赖并重绑所选对象；直接替换共享资源会影响未选引用者时，规划拒绝并要求补选或取消。课程和日程子对象发生 ID 冲突时，只重绑所选父对象中的冲突项及其关联引用。

便携对象构造使用明确字段组。Agent 连接与偏好可以单独选择，原始密钥、三种权限和本机执行资格不作为导入授权。旧完整 JSON 沿用既有预算，不从旧格式兼容默认值补造 Agent 配置。聊天恢复只生成可阅读历史，保留版本与附件引用，去除运行、审批、队列和重做资格。

设备偏好使用来源平台与组身份。当前平台无法应用的分组保留在计划的 `unsupportedGroups` 中，不生成写入目标。以上规划和合并是纯计算；真正写入须由存储拥有者在维护边界中执行。

## 持久恢复协议

`SelectiveRestoreCoordinator` 要求宿主提供排他的恢复边界。所有参与者先准备并验证原值和目标，首次 journal 固定对象映射、数据世代和阶段；预检失败不开始业务写入。已经保存但回复丢失的阶段必须读取实际存储确认，不能重新分配身份或准备另一组目标。

参与者按附件、主库、凭据、学校站点、设备偏好、知识和聊天的顺序执行。每阶段核对实际目标后再记录进度，全部确认后才清理暂存和 pending 标记。任一阶段结果未知时保留 journal，由相同的存储拥有者继续，不能用旧内存数据冒充实际状态。

原生 journal 使用双槽与完成墓碑；浏览器使用受控偏好存储。二进制附件暂存位于专用私有目录或独立 IndexedDB，不使用原设备文件路径。基础协调器只执行参与者协议，应用级排空、冻结和启动恢复由组合层接入。

[恢复协调回归](../test/backup/selective_restore_coordinator_test.dart)覆盖固定目标、准备失败、中断继续、回执丢失和目标漂移；[journal 回归](../test/backup/selective_restore_journal_test.dart)覆盖双槽、版本拒绝、损坏和完成清理。
