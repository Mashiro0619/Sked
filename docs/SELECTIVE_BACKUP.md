# 对象选择备份与恢复

选择性备份使用版本化的对象清单和二进制归档。本文随归档、对象规划、恢复协调和正式入口的独立提交逐步补齐；交付进度见[实施计划](AGENT_IMPLEMENTATION_PLAN.md)。

## 归档格式与校验

ZIP v1 使用 `manifest.json`、逐对象 JSON 和按摘要标识的二进制文件。清单声明对象身份、依赖、路径、长度和 SHA-256；读取核对清单及文件，拒绝未声明项、重复项、错误摘要、循环依赖、链接、加密归档、路径越界及不支持的版本，不把 ZIP 路径解压到文件系统。

单份附件最多 32,000,000 字节，整个归档及解压内容各有 128 MiB 上限；单对象 16 MiB，清单 2 MiB，最多 2,048 个对象。聊天附件元数据与二进制分开表示，缺少文件内容时必须保留缺失事实，不能访问原设备路径。

对象通过类型与稳定 ID 定位，设备配置额外包含来源平台和分组。归档承载由各拥有者过滤的便携数据，密钥、Cookie、系统授权与运行许可不得作为导出内容。模型和编解码器不自行写入业务仓储，也不提供界面入口。

## 对象选择与依赖规划

同稳定 ID 的选中对象替换原位置，不存在则新增；同名不合并，空分组不清空本机整类数据。选中父对象的子集合可以恢复为空，未选对象保留。

课表与节次时间集、聊天与附件分别保存明确依赖。必要依赖与本机内容相同时复用，冲突时只复制该依赖并重绑所选对象；直接替换共享资源会影响未选引用者时，规划拒绝并要求补选或取消。课程和日程子对象发生 ID 冲突时，只重绑所选父对象中的冲突项及其关联引用。

便携对象构造使用明确字段组。Agent 连接与偏好可以单独选择，原始密钥、三种权限和本机执行资格不作为导入授权。旧完整 JSON 沿用既有预算，不从旧格式兼容默认值补造 Agent 配置。聊天恢复只生成可阅读历史，保留版本与附件引用，去除运行、审批、队列和重做资格。

设备偏好使用来源平台与组身份。当前平台无法应用的分组保留在计划的 `unsupportedGroups` 中，不生成写入目标。以上规划和合并是纯计算；真正写入须由存储拥有者在维护边界中执行。

## 持久恢复协议

`SelectiveRestoreCoordinator` 要求宿主提供排他的恢复边界。所有参与者先准备并验证原值和目标，首次 journal 固定对象映射、数据世代和阶段；预检失败不开始业务写入。已经保存但回复丢失的阶段必须读取实际存储确认，不能重新分配身份或准备另一组目标。

参与者按附件、主库、凭据、学校站点、设备偏好、知识和聊天的顺序执行。每阶段核对实际目标后再记录进度，全部确认后才清理暂存和 pending 标记。任一阶段结果未知时保留 journal，由相同的存储拥有者继续，不能用旧内存数据冒充实际状态。

原生 journal 使用双槽与完成墓碑；浏览器使用受控偏好存储。二进制附件暂存位于专用私有目录或独立 IndexedDB，不使用原设备文件路径。基础协调器只执行参与者协议，应用级排空、冻结和启动恢复由组合层接入。

[恢复协调回归](../test/backup/selective_restore_coordinator_test.dart)覆盖固定目标、准备失败、中断继续、回执丢失和目标漂移；[journal 回归](../test/backup/selective_restore_journal_test.dart)覆盖双槽、版本拒绝、损坏和完成清理。

## 应用拥有者与恢复接线

`SelectiveBackupService` 由 `AppRuntime` 持有，在 Agent 各仓储和设备偏好拥有者构造完成后只绑定一次。`AppBackupController` 提供主库、学校站点和共同维护预约；服务组合聊天、知识、连接凭据、设备偏好、附件及专用暂存仓储。准备、导出和已经接受的恢复使用这些实际拥有者，调用者只提供选择和取消信号。

设备偏好的实际布局与开发者偏好实例在主库载入前绑定。`AppBootstrap` 创建并持有这两个实例，`MyApp` 借用同一组；恢复期间不会重新创建另一份偏好拥有者替换已冻结的实例。应用关闭先排空已经接受的工作，再按拥有关系释放服务和偏好实例。

### 预约内读取与写后核对

恢复先取得应用维护预约，阻止新的普通业务写入，并排空主库、学校站点、连接保存、设备偏好、聊天、知识和附件已经接受的操作。聊天和知识的恢复接口保持普通写门禁关闭，在异步读取前后重新验证预约拥有者；不会用较早的内存副本覆盖当前实际存储。

所有参与者在首个业务写入前准备固定目标。附件先进入独立暂存仓储；准备过程未能返回完整目标时，附件参与者清理自己的部分暂存内容。随后每一步都读取实际拥有者，对照 journal 中的原值与目标值决定是否写入。主库、聊天、知识、学校站点和设备分组的目标必须经过实际读回确认；不能仅凭内存状态或阶段记录声称成功。

连接恢复不从归档恢复密钥或运行授权。同一目的地保留其本机凭据；目的地改变时处理旧目的地凭据，并通过连接拥有者重新核对最终绑定。缺失的本机密钥继续保持缺失，不能因归档中存在连接地址或模型而补造可用凭据。

### 启动、重试与旧接口共存

正常启动和存储重试在开放普通写入前检查恢复记录。没有待恢复记录时，这条路径不因此初始化聊天或知识正文。有记录时只继续已经固定的目标，不重新分配对象身份或重新准备另一套恢复；即使 journal 已记录完成，清理前也要核对所有最终状态。损坏、未来版本或无法确认的存储保持拒写并保留恢复材料。

历史重做、旧整体恢复和选择恢复共享维护门禁。已有历史重做身份或 pending 标记时不能接受新的选择恢复；并存的恢复标记不能互相覆盖或同时重放。旧 `prepareJson/exportJson/importJson` 等整体备份接口保留原调用方式，新增门禁阻止它们越过仍待完成的选择恢复。

导出取消传递到实际附件读取；即使读取仍在等待，取消也必须释放导出占用。尚未完成的导出不能作为完整归档返回。这些约束属于应用服务，不依赖新的页面或 Agent 工具入口。

## Agent 工具与产物保存

`backups.inspect` 列出当前对象，或通过 `sourceId` 检查已附加的 ZIP 和旧完整 JSON；结果分页提供对象 ID 与依赖，后续选择使用这些确切 ID。设备对象同时提供来源平台、分组与 `supportedOnThisPlatform`。

`exports.prepare` 使用 `format: 'backup_zip'`、`objects` 和 `attachmentIds` 生成固定的内存二进制产物。选中聊天会保留其附件元数据；文件字节必须独立选择。取消 Agent 运行作用域会中断仍在等待的附件读取，未完成的产物不会发布。

`exports.write` 准备保存操作，`external.commit` 才调用宿主保存。宿主对二进制产物使用 `ExportService.saveBytes`，文本产物继续使用 `saveFile`；结果应报告实际保存、取消或失败，生成归档字节本身不表示文件已经保存。

`backups.prepare_restore` 明确提供对象时使用选择性恢复，预览以 `unsupportedGroups` 列出异平台设备分组，完成结果以 `skippedDeviceGroups` 报告跳过项并保留本机设置。未提供对象的调用保留旧完整 JSON 恢复兼容路径。恢复由应用持有固定 journal，排空运行时只排除正在等待本次结果的发起 Agent 运行，避免等待自身。

内置 `export-and-backup` 与 `restore-and-clear` Skills 的 1.1.0 版本说明对象选择和设备兼容性，继续遵守现有三种权限模式。

[Agent 工具回归](../test/backup/selective_backup_tools_test.dart)覆盖对象选择、权限、设备偏好拥有者、异平台预览与跳过、附件读取取消、选择性恢复和发起者排空。模型与保存目的地使用确定性替身，测试范围不包含实际平台文件选择器、真实模型 API 或实体设备验收。
