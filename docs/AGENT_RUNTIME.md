# 内置 Agent 的运行行为

本页说明已接入的实现与恢复边界；产品范围和分阶段验收见[实施计划](AGENT_IMPLEMENTATION_PLAN.md)。测试 provider、真实模型 API、组件测试和原生设备验收分别记录。

## 会话附件

会话允许选择任意类型文件，单份最多 32 MB、每条消息最多 20 份。先把原始字节保存到应用私有文件或 Web IndexedDB Blob，核对实际长度和 SHA-256 后才发布引用；添加附件只保存本地草稿，不自动发起模型请求或导入业务数据。

附件绑定具体用户消息，支持正文为空的请求。单个请求的原始文件合计最多 48 MB，按当前 API 原生内容块发送；编码前核算 Base64 开销，编码与读取可以取消。当前请求的工具往返保留完整文件，旧历史文件由用户显式重新附加。服务拒绝、缺失或损坏时保留引用并报告原因，不换模型或退化为文件名。保存引用失败后的重试核验也可取消，复用同一文件身份；数据世代或输入边界改变会拒绝旧待发布引用。

实现、兼容来源与验证入口见[附件存储与协议](AGENT_ATTACHMENTS.md)。会话格式 v5 在 v4 的二进制引用之上保存轮次、回复版本和重做进度，继续读取 v1–v4；聊天 JSON 不保存原设备路径或二进制正文，旧网页/文本来源继续按原有规则读取。

## 提醒动作与只读核对

提醒入口只接受设备运行时实际保存、仍属于当前投影的通知身份。读取可操作提醒和稍后提醒状态不清理过期存储，也不根据模型参数伪造通知载荷。稍后提醒复用通知卡片的十分钟动作；执行前重读身份，完成后读取保存状态，过期卡片不能报告成功。外部回执核对只读取结果，不再次延后提醒。

实现与回归：[通知服务](../lib/services/agenda_notification_service.dart)、[运行时存储测试](../test/services/agenda_notification_runtime_store_test.dart)、[通知服务测试](../test/services/agenda_notification_service_test.dart)。

## 清空本机凭据

统一连接的 active/pending 安全存储槽位位于普通数据目录之外。清空本机数据时先移除两个槽位并逐一读回核验，再删除最后可恢复的主库存档；删除未能核验时保留主库存档并报告失败。测试覆盖安全存储拒绝实际删除的路径，不能据此替代各系统钥匙串的原生验收。

实现与回归：[清空服务](../lib/services/app_data_clear_service_io.dart)、[清空失败测试](../test/services/app_data_clear_service_io_test.dart)。

## 模型运行、权限与恢复

运行时通过独立 UI 状态发布流式文本，消息持久化与主库事务分离。会话保存输入队列，区分当前步骤调整与后续请求；停止、关闭功能和收紧模式会取消尚未提交的步骤。重启后需要显式继续，并先核对中断工具的持久回执；新消息或宿主操作不能绕过未决写入。

只有只读计划、逐次询问和完全权限三种模式。计划可以查询和生成候选，但不能提交业务修改；询问批准仅绑定当前计划；完全权限允许直接执行通过校验的计划。模型无法修改自己的权限模式。HTTP 传输确认与业务审批分离：计划/询问模式向当前连接首次发送前确认，许可只对进程内同一端点、协议、模型和凭据引用复用；完全权限按当前政策允许 HTTP，不伪造显式许可。连接变化或政策收紧重新检查。

运行时在响应发布、工具执行、审批展示和上下文发送前核对当前 API Key 的完整值。协议续传项、工具结果和审批预览检查实际嵌套字符串值与字段名，避免引号或反斜杠经过 JSON 编码后漏检；工具调用 ID 同样检查，新工具参数先严格解码再检查。历史中的工具参数和工具正文只按声明的 JSON 字段解码一次，普通正文及结构内的字符串不继续解析，也不猜测其他凭据。发现旧历史含当前密钥时拒绝新请求并保留原存档，不自动清洗消息。

协议调用先匹配本次请求声明的编码函数名，再接受同一声明集合内完全一致的逻辑名。发现结果使用逻辑名，下一轮按最新公开工具列表校验，未公开工具继续拒绝。历史续传统一使用编码函数名。

工具结果包含当前密钥时只保存安全的结果未知代码，停止后续工具；预算摘要仅保留已通过同一检查的操作身份，不再从被拒绝的结果取值。[运行回归](../test/agent/runtime/agent_runtime_controller_test.dart)覆盖实际 HTTP 解码后的转义参数、调用身份、含引号与反斜杠的密钥、嵌套值与字段名、旧历史的零传输，以及字面转义文本的正常发送与保存。

模型请求默认总限时五分钟，等待响应头和流中无数据的限时均为两分钟，以容纳模型思考或服务排队。应用级运行时间、轮次和 token 预算仍独立生效；用户停止会立即取消等待及活动连接，不需要等超时。协议回归以虚拟时钟验证较长首响应、帧间等待和即时取消，不依赖真实服务响应速度。

业务审批和 HTTP 传输确认显示后，用户阅读与决定的时间不计入工具执行限时或整轮运行限时；宿主操作卡发起的审批遵循同样规则。批准或拒绝后按原先剩余执行时间继续计时，不重新获得完整预算；准备、读取、保存与实际执行仍受限时约束。等待期间停止、关闭功能或维护取消仍立即生效，迟到批准不能重新启动计时或动作。[运行回归](../test/agent/runtime/agent_runtime_controller_test.dart)使用可控时钟验证长时间审批、剩余预算、拒绝与停止。

长会话上下文按完整工具调用/结果组压缩，保留用户原文、操作身份与已加载技能引用；超过预算时要求缩小查询。原始历史保持可读，不将摘要当作执行回执。宿主动作先保存实际计划/操作身份，再开始执行，因此“已执行但回复丢失”可从主库账本核对，不重复动作。

会话格式从 v3 起按运行和请求身份保存实际用量、工具尝试、结果及模型选择；后续格式继续兼容 v1 和 v2，旧应用拒绝读取较新格式，避免写回时丢失记录。模型请求发送前先保存 pending，收到结果后将回复与用量一起保存；重复 usage 流事件覆盖同一请求，不重复累加。中断、取消或重启未取得结果时保留 unknown；缺失缓存/推理用量为 null，不能报告为零。普通显式继续创建关联旧运行的新记录；历史重做在中断后继续其已保留的运行身份，均不会在加载聊天时自动调用模型。多模型、思考强度、发送快照和排队请求的规则见[模型选择](AGENT_MODEL_SELECTION.md)。

Responses 流明确返回 `response.incomplete` 时，会话将该次模型请求记录为已知失败，保留服务实际报告且通过校验的用量，不把未完成任务误记为请求结果未知。解码器在同一事件内读到合法用量后因输出或 token 预算报错，也先交付用量再交付错误，不执行未完成或超预算的工具。未报告的用量继续未知；流直接断开、没有明确终态仍为 unknown。对应[提供方协议回归](../test/agent/provider/provider_client_test.dart)及[真实协议到会话存储回归](../test/agent/runtime/agent_runtime_controller_test.dart)使用合成 SSE 验证，不代表付费服务或设备联调。

服务改为返回 `application/json` 时，Responses 按实际 `status` 进入相同的完成、未完成或失败处理。正常回包的 `error: null` 不表示请求失败；非空错误仍拒绝执行。聊天显示 API 返回的错误消息与错误码，并附带已知 HTTP 状态。错误响应最多读取 32 KiB；已收到 HTTP 拒绝状态后，正文读取超时仍保留该状态与已读到的有效消息，主动取消继续按取消处理。HTTP 拒绝和内容类型错误保留最多前 32 KiB 正文，包括非标准 JSON、HTML、纯文本和截断内容。JSON 或 SSE 解码失败保留实际响应或出错事件数据。流式累计诊断保留末尾 32 KiB，SSE 单个错误事件最多展示 32,768 个 Unicode 字符，省略部分用省略号标记。诊断按长度限制读取，剔除控制字符并隐藏当前请求凭据的原文、单层 JSON 转义回显及带引号的凭据字段，使用可选择的纯文本呈现。原始响应以可复制纯文本显示，保留结构和首尾空白，附带已知 HTTP 状态与服务错误码。本地协议、预算和网络失败显示对应原因。未知工具同时保留模型返回的函数名称。普通请求中已经展示且通过凭据检查的文字在 API 失败后继续可读、可复制；重新生成回复失败时仍丢弃替换草稿并保留原回复。服务诊断只保留在本次运行的内存状态，新的请求清除旧诊断，会话存档仍仅保存稳定错误码，重启后归档保留错误分类，运行期诊断不恢复。JSON 未完成响应同样保留合法用量与明确终态，缺失用量和超预算规则与 SSE 一致。

选择性备份工具按明确对象和独立文件选择生成 ZIP；设备偏好按平台分组，清单、计划和结果均保留不支持项。恢复进入独立维护边界，排空侧写后固定各仓储目标和阶段；发起运行不会等待自身，其他旧运行失效。聊天只导入可阅读历史，不恢复旧执行身份。文件导出读取继承当前运行的取消信号，协议与故障验证见[选择性备份](SELECTIVE_BACKUP.md)。

conversation.get、conversations.get、runs.status 和会话导出提供已记录运行的统计；历史 v1 会话没有过去的用量证据。工具尝试区分未开始、完成、失败和未知，费用没有可信单价时保持 unknown。记录沿用会话保留、删除和大小上限，不进入正常模型上下文或完整业务备份。相关恢复与迁移见[用量存储回归](../test/agent/conversations/conversation_usage_test.dart)。

实现与回归：[运行控制器](../lib/agent/runtime/agent_runtime_controller.dart)、[上下文](../lib/agent/runtime/conversation_context.dart)、[运行回归](../test/agent/runtime/agent_runtime_controller_test.dart)、[恢复回归](../test/agent/runtime/operation_recovery_test.dart)。

## 全域工具宿主

工具宿主按运行按需发现 schema 和共享 Skills，所有工具参数通过严格字段校验。六类资源查询覆盖非当前、隐藏及停用域，分页结果明确是否完整；查询不切换或启用工作区。固定选择集合保留实际 ID，公共 patch 只作用于准备时完整选中的对象，数据世代或版本变化后旧选择失效。

固定资源类型的查询工具在 `fields` 参数中列出实际允许的字段，省略该参数使用默认视图。`resources.describe` 提供查询字段与各视图字段集合。选择集合只返回资源引用，其 `fields` 参数按兼容规则忽略。字段错误返回允许字段和具体参数名，运行时将这些纠错信息传回模型并保存到工具详情。

新操作准备时省略 `operationId`，由宿主分配身份，重试同一操作时原样复用已返回的 ID。工具注册表为准备和回执查询参数分别提供此说明。主库和外部操作身份均由数据世代、序号和 UUID 组成。无效身份会返回纠正方式及 `operationId` 参数名，合法重试继续核对原操作内容与回执。

分页 schema 与执行边界使用同一上限：能力检索每页 16 项、技能检索 24 项、会话历史 50 条、单条历史正文 8,000 个 Unicode 字符。通用资源分页仍最多 100 项，并独立遵守结果字节预算；模型不会再因采用 schema 公布的合法页数而撞上更小的隐藏上限。见[分页契约回归](../test/agent/tools/pagination_contract_test.dart)。

主库修改通过 prepare/commit 和持久操作回执执行，支持查看完整差异及有条件撤销。标准资源与设置计划记录目标、父资源元数据、共享节次及联动设置的读取依赖，固定准备时的 ID 和时钟；提交时在当前已保存快照上重新编译，并要求完整前后差异仍与审批一致。无关已保存编辑可以保留，同对象、语义依赖和未保存 UI 草稿仍会阻止提交；撤销记录使用实际提交位置。宿主导入/显示等 prepareDraft、待提交撤销及已被其他 Agent 提交推进的回执序列仍保留较严格的重新准备要求，不代表所有路径都支持细粒度并发合并。

工具结果超出预算会要求缩小分页或字段，不把截断解释为数据不存在。并发边界见[提交竞争回归](../test/application/mutation_coordinator_test.dart)和[共享保存门禁](../test/controllers/app_session_mutation_test.dart)。

设置描述通过 adapterTool 指向拥有该语义的入口。Agent 开关属于可准备的普通设置，权限模式仍只能由用户切换；旧解析配置只读保留用于迁移，不再提供第二套连接写入口。

实现与回归：[工具宿主](../lib/agent/tools/application_tool_host.dart)、[选择集合工具测试](../test/agent/tools/selection_tool_test.dart)、[资源字段覆盖](../test/agent/resource_field_coverage_test.dart)。后续适配器在应用组合层注册后才向正式会话提供完整能力。

会话活动列表先显示动作和已知对象类别，查询日期范围及搜索词使用对应工具的白名单参数；读取单个对象时仅从已完成且种类、对象及父级身份匹配的宿主投影取得名称。摘要有长度与解析预算，不扫描来源正文、备注、凭据、URL、未知字段或模型解释；无可靠摘要时保留通用名称和原始详情入口。日期按本地语言与本地时间显示，保留实际查询的两个端点，不将结束边界改写为包含该日。活动的完成、失败、待核对及未开始状态仍由原记录决定，摘要不授予权限、不替代操作回执。见[活动摘要回归](../test/agent/ui/agent_activity_summary_test.dart)。

## 网页交接与课表候选

网页来源先压缩和校对，再以固定 handoffId 原子保存新会话、初始请求和不可变附件。重复交接复用已有会话，同身份但内容或目标改变会被拒绝。交接记录保留来源、截断状态、日期和数据世代；创建会话不意味着远端推理或业务保存已成功。

新交接的初始用户消息使用校对时语言保存可读的导入任务，缺少网页标题时使用本地化来源名；技能路由、来源不可信、权限与缺失事实约束放在宿主系统上下文。该上下文必须同时匹配本地 handoff 记录、原始请求身份、来源摘要及校对元数据，只随原请求及其显式继续生效；后续普通提问、仅带来源的消息和导入的历史不能触发它。用户仍可修改或取消导入要求，宿主指引明确让后续用户修正优先；运行中的调整撤销旧作用域，新模型请求不继承原导入任务指令。网页正文与标题不拼入系统指令。现有会话消息保持原文，不通过加载或升级自动清洗旧英文提示，也不为展示调整存档 schema。

候选解码是有界纯计算，与模型请求和主库写入分离。imports.prepare 要求明确创建或替换目标，并校验实际开学日期、周次、时间、作息引用及来源所属会话；缺失事实不得静默填写为当前日期。准备后仍需 mutation.commit 按会话模式执行，最终回执决定是否导入成功。

实现与回归：[交接](../lib/agent/imports/school_web_handoff.dart)、[候选工具](../lib/agent/imports/school_import_tool_adapter.dart)、[导入专项](../test/agent/imports/school_import_tool_adapter_test.dart)、[交接去重](../test/agent/imports/school_web_handoff_test.dart)。

## 测试存储边界

默认会话存储在 test/flutter_test_config.dart 中替换为每项独立的内存实例，覆盖直接构造 AppRuntime 的历史测试。一个测试内的重启共享同一实例；后续测试换新实例，迟到回调只持有旧实例。显式构造原生会话存储的专项继续使用系统临时目录验证真实 IO，不由默认替身替代。

使用真实文件的 AppRuntime 测试在清理临时目录前等待 shutdown.quiesce()，再 dispose 并等待会话关闭；只调用同步 dispose 不表示启动迁移或异步写入已经完成。清理不依赖固定延时。

恢复测试分别验证便携备份和本机 journal：便携文件排除 Agent 本机配置与账本，journal 使用恢复专用编码保留这些状态，两者均不得包含密钥。每次恢复采用独立数据世代并发布 ledger 变更；学校站点保留自身格式版本，不能跟随主库版本升级。

## 设备、站点和系统动作

主库提交和通知效果分别报告。现有 AgendaCoordinator 为观察到的每次持久提交生成通知票据，绑定数据世代、提交 revision、agenda 版本和投影 epoch；操作查询另携带持久 operationId 与 sequence。排程等待中为 pending，较新提交替代尚未完成的工作时为 superseded；完成、权限阻断、失败、不支持和无需重排分别报告。状态取自该次投影返回值，不借用全局 lastError；已保存数据始终保持 committed。

这些通知观察最多保留 256 次，属于当前协调器实例。重启、未绑定宿主或记录已淘汰时，持久业务回执仍可核对，通知效果返回 unknown，不重发通知来猜测旧结果。applied 仅说明排程已更新，不表示系统实际投递。界面在“修改已保存”之下单独显示提醒排程结果，见[提交效果回归](../test/services/agenda_commit_effect_test.dart)与[操作卡](../test/agent/ui/agent_operation_card_test.dart)。

操作卡按 operationId 读取当前宿主的观察，仅在对应票据变化时刷新卡片；原始消息和业务回执不改写。重新打开会话也重新核对，宿主解绑后立即显示 unknown，不永久沿用历史 pending 或 applied，也不发起轮询或重复排程。见[会话内通知结果回归](../test/agent/ui/agent_notification_effect_view_test.dart)。

外部适配器共用先记录计划、执行并读回的协调器。设备布局与偏好写入等待实际 flush；窗口、通知、系统设置入口按平台能力返回支持情况。打开自启动设置页只证明入口已打开，无法观测授权时保留 unknown。未绑定应用服务或平台不支持时返回明确错误。

学校站点使用稳定的版本句柄及共享写队列；预览期间发生其他读写不能改变该预览的版本前提。通知动作只操作当前设备拥有的真实提醒，外部核对使用原操作身份，不重复系统动作。

实现与回归：[平台适配器](../lib/agent/tools/platform_tool_adapters.dart)、[设备适配器](../lib/agent/tools/device_tool_adapters.dart)、[平台回归](../test/agent/tools/platform_tool_adapters_test.dart)、[设备回归](../test/agent/tools/device_tool_adapters_test.dart)。

## 文件、维护和显示工作流

确定性文件检查与准备支持课表/日程 JSON、ICS、节次和备份，保留大小、目标、缺失日期与兼容报告。导出、工作区切换、页面导航、恢复和清空使用 external.commit；纯主库计划使用 mutation.commit。维护先暂停旧运行并排空已接受写入，恢复后数据世代使旧计划失效。

courses.display.list 返回真实周投影中的冲突组；courses.display.prepare 的 set/reset 只选择展示课程，复用 UI 服务并清理等价旧键，不改变课程时间。navigation.range.prepare 复用显示范围 reducer，保存范围及必要焦点调整。两者均支持停用域管理、完整差异、模式门禁与撤销，不隐式切换或启用工作区。

实现与回归：[工作流适配器](../lib/agent/tools/workflow_tool_adapters.dart)、[工作流测试](../test/agent/tools/workflow_tool_adapters_test.dart)、[显示范围测试](../test/agent/tools/display_range_tool_adapters_test.dart)。

## 会话管理与统一连接

会话管理支持查看历史、归档/恢复、重命名、删除、保留设置和导出；写动作绑定真实会话版本及运行作用域，不能复活已删除会话。导出产物只包含获准的对话内容与结果，不包含安全凭据。

会话创建、改名、删除和归档回执直接显示宿主快照中的会话标题及已确认动作；归档与恢复使用各自状态，不把准备或未知结果写成完成。查看入口仅为仍存在的已确认目标开放，先保存当前输入草稿，再选择实际会话；查看归档会话只打开历史，不恢复会话或请求模型。删除结果及已被删除的历史目标不提供失效入口。新增归档／恢复状态文案提供英、简中、繁中，其他已提供语言暂沿用显式英文回退。

连接工具使用宿主安全输入句柄，原始密钥不经过模型参数。配置替换、清除、连接诊断和模型列表均绑定已保存的目的地与版本。诊断明确区分传输可达和实际工具调用能力；模型列表有边界，后续分页读取同一回执，不再次发出网络请求。共享偏好可准备修改，权限模式仍由用户控制。

密钥输入等待绑定发起运行和当前宿主。停止、维护排空、退出或宿主解绑会取消等待并关闭该次输入框，不需要用户再提交或取消；其上后来打开的其他对话框保留。宿主忽略取消后迟到返回的密钥立即丢弃，不建立句柄、不保存到连接或会话。输入框的正常提交、手动取消与迟到输入清理分别由[输入界面回归](../test/agent/ui/agent_credential_input_test.dart)、[工具回归](../test/agent/tools/agent_control_tool_adapters_test.dart)和[应用排空回归](../test/agent/agent_application_test.dart)验证。

设置页面保存携带其编辑时的已提交配置，应用配置队列在真正执行、初始化结束以及写入前核对该快照。排队期间其他页面或 Agent 已保存较新配置时，旧草稿保存失败并保留输入，不覆盖新连接、模型目录或偏好；凭据核验期间发生的配置变化同样拒绝写回。连接与偏好仍只保存各自字段，正在运行的请求保留已接受的配置快照。

实现与回归：[连接控制工具](../lib/agent/tools/agent_control_tool_adapters.dart)、[会话工具](../lib/agent/tools/conversation_tool_adapters.dart)、[连接控制测试](../test/agent/tools/agent_control_tool_adapters_test.dart)、[会话工具测试](../test/agent/tools/conversation_tool_adapters_test.dart)。

## 应用所有权与双端入口

AppRuntime 持有一个 AgentApplication，各布局从侧边导航进入完整聊天，共享会话和运行。功能关闭隐藏入口并停止未提交步骤，保留已有会话；关闭聊天或返回来源页不会转移运行所有权。配置页面分开连接与偏好草稿，输入区支持附件、停止、继续和有序追加请求；操作卡从真实计划与回执提供预览、撤销和对象查看。

后续输入先持久保存。自动队列在每次启动前核对会话的实际占用者，只接续自己认领的运行；收尾回调启动另一运行时继续等待它的真实完成，不把忙碌拒绝归到该运行，也不移除它的审批或吞掉待处理输入。运行失败或结果未知时停止自动消费并保留后续输入，显式继续仍从原有队列恢复。恢复请求和新追加输入分别持有本次自动接续资格，旧恢复请求的收尾不能撤销较新请求的资格。[队列归属回归](../test/agent/runtime/agent_runtime_controller_test.dart)使用真实运行时、提供方完成信号和审批，覆盖收尾重入、运行互斥、失败保留及并发恢复边界。

设置和设备回执与审批预览按已登记字段、实际面板角色及动作使用可读名称；保留课表与日程的区分，不把内部键作为唯一摘要。面板宽、高和并排宽分别命名；旧开发预览偏好不会混称为正式 Agent 开关。连接、平台与窗口动作的标签只描述对象或请求，不推断支持、授权或完成状态；未知历史键仍可查看原始详情。仅补充缺少的六个面板名词，提供英、简中、繁中，其他已提供语言暂用显式英文回退。

知识与选择性恢复的操作卡根据宿主回执中的前后记录显示对象名称，不以内部对象键或技术 JSON 充当可读结果。仅确认生效后显示已添加、已更新或已删除；尚在准备、失败或结果待核对时只显示对象名称，知识预览未提供名称时显示技能或记忆类别，并保留宿主的状态标题。内置 Skill 首次产生本地覆盖、停用或恢复原版在确认后都显示更新；本地覆盖记录的新增或移除不代表内置 Skill 被创建或删除。仅确认已恢复的课表、节次时间集和日历提供原有只读对象页入口；知识不添加新的导航类型。展示不改写持久回执、成功状态或撤销规则。[真实回执卡片回归](../test/agent/ui/agent_external_receipt_view_test.dart)通过生产工具准备、提交、结果说明和组件渲染验证英文、简体中文、繁体中文及窄窗放大字号，并注入知识存储的写前拒绝与写后未知结果，核对未确认回执不显示完成措辞。

标准资源的准备回执同样只显示对象名称。未确认结果不根据计划中的动作或新身份宣称完成，也不开放尚未确认写入对象的查看入口。已经提交的主库修改继续显示保存成功，通知观察未知只单独报告提醒状态；外部效果已经确认而最终回执仍需核对时，保留实际生效的行文与待核对标题。审批预览使用“添加、编辑、删除”等中性动作词说明拟议变更，保留每个对象的完整前后值和分页展开。[标准计划与审批回归](../test/agent/ui/agent_unconfirmed_operation_view_test.dart)读取真实准备回执和运行时审批详情，并分别核对主库成功、未知提醒观察及已生效的外部 partial 回执。

学校站点的整表回执按稳定 ID 对照前后记录，只列出实际新增、字段变化和删除的站点名称，不把未改站点称为更新，也不按同名或同 URL 合并身份。卡片计数对应当前可见的实际变更行；完整列表相同显示零项，只有顺序变化时显示一项站点列表结果。准备中或待核对的行保持中性，不新增对象导航；原回执、前后记录和更多变更标记保持不变。缺少唯一稳定 ID 的历史形状继续保留原始详情，不猜测逐对象差异。[学校站点回执回归](../test/agent/ui/agent_school_site_receipt_view_test.dart)通过真实导入与创建、修改、删除工具核对三语结果、同名对象、未选保留及无变化和顺序变化。

旧独立文字解析、解析设置、专用结果页和网络执行链路随新入口切换退役。网页仍先压缩校对，然后创建一次 Agent 会话并进入可见页面；直接粘贴文字使用普通会话。确定性 JSON、ICS 和节次导入入口继续使用各自领域解码。

清空前先排空写入并冻结会话存储。清空成功后，即使退出回调返回也保持冻结；失败后需要显式恢复读取真实侧存储，旧内存不能自动重建文件。测试覆盖两个会话并发维护、迟到回复、关闭与恢复，原生权限和物理设备结果另验。

最终关闭同步拒绝新运行和普通聊天编辑，只允许关闭开始时已接受的运行保存待完成的工具回执、用量及附件投递结果。运行结束后立即撤销该写入资格；即使提供原运行 ID，也不能改名、归档、修改草稿或追加新的用户请求。清空和销毁始终拒绝所有迟到写入。

## 历史重做与整段撤销

外部协调器的审批内容与持久回执可由拥有者分别提供：`changes` 展示完整本次变更，`receiptChanges` 保存对象引用、版本和摘要。知识正文及逆变更保存在知识仓储，不复制到通用操作账本；外部执行结果也只返回拥有者的回执引用。该能力不改变三种权限或外部效果核对流程。

`MutationCoordinator.prepareUndoMany` 接受宿主持久批次身份和精确操作 ID 集合，按原提交序号逆序预检全部操作，将最终逆变更合成一次主库提交。任一目标冲突、回执过期或整批超预算时，不写入任何逆变更；重复批次核对同一持久回执。已经被整批撤销的单条操作不再次撤销。该接口只负责主库逆变更；正式历史流程同时预检知识仓储的拥有者票据，在共同写入边界内按持久阶段完成主库和知识的撤销，不表示任意外部操作均可撤回。

正式聊天以宿主记录的完整轮次及工具调用归属选择撤销范围，预检前停止运行、撤销审批和队列；缺少完整归属、存在不可逆效果、目标冲突或容量不足时整段不开始。旧消息后缀、原运行及附件引用保存为历史，只发布选中的一个新请求。重做失败后复用已固定的运行身份继续，多个页面重复继续共用同一流程。回复重新生成只发布文字版本，不提供工具或执行器。

应用启动先检查独立恢复标记，正常启动保持聊天按需加载；有标记时在开放普通写入前核对实际主库、知识与聊天回执，完成已接受的逆变更后等待用户继续模型请求。存储重试也先恢复原预约；清理标记的回执丢失不允许直接释放未经核对的状态。协议与正式双端回归见[历史与回复版本](AGENT_HISTORY.md)。
