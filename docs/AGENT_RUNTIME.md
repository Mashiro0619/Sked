# 内置 Agent 的运行行为

Agent 由应用拥有，每个会话有独立的执行对象。聊天页面读取同一执行记录的展示视图，关闭页面不会终止已经接纳的保存。

## 执行链与权限

`RustAgentUiDelegate` 发送类型化命令，Rust `RuntimeManager` 持有每个会话的运行、队列、问答、压缩和历史状态。Rig 负责模型与工具循环，`RustAgentBusinessHost` 将业务调用交给 Dart `OperationExecutor` 完成领域准备、授权、保存与回执。

模型通过一次业务工具调用完成一次修改，例如 `mutation.apply`、`backups.restore`。宿主生成操作身份，模型不填写或搬运新操作的 `operationId`，公开目录不提供准备后再提交的双调用流程。当前工具调用按执行顺序处理，单次批量修改使用一次业务事务。

候选由当前业务调用持有，预览返回、拒绝、完成或失败后立即释放；持久操作记录继续保存实际影响与回执。

- 计划模式返回业务预览。
- 确认模式在当前调用中等待用户决定。
- 完全权限按当前授权执行。

审批描述实际对象和影响。原生桥接向界面传递每项变更的完整修改前后内容，以及宿主持有的关联对象预览；模型使用的精简摘要不替代人工审批详情。新运行读取原生会话的当前权限，读取期间权限发生变化则重新核对；删除或恢复同一会话不会复用旧权限。运行中收紧权限立即更新业务作用域并结束旧审批。模型参数、Skill 正文和来源资料不能替代宿主许可。未知工具、错误参数和已经变化的资源回送模型纠正；已保存但结果尚未核对的操作进入回执核对流程。

普通任务没有累计 Token、模型轮数、工具次数、强制收尾请求或普通执行时限。用量记录与执行控制分开；用户停止、实际服务终态和真实故障决定运行何时结束。连接诊断保留专用探测行为。

## 输入、队列与会话标题

首条用户输入成功持久化后，应用以当次连接、模型和完整首消息发起一次独立的 AI 命名请求，异步生成简短标题。请求不携带工具，服务用量记录在会话的标题元数据中；主任务继续使用自己的请求及用量。命名期间显示临时标题，失败保留原值，手动改名和明确交接提供的标题优先。HTTP 命名在原传输许可通过后开始。分页和会话切换保留来源身份，保存时再次核对首消息和手动改名状态；删除、来源失效、配置变化和应用退出结束旧命名请求。标题保存保留原活动时间，空会话草稿不进入历史。

运行中发送默认进入可见队列。“立即补充当前任务”取消尚未执行的旧步骤，已经接纳的业务写入先完成结果核对。队列项使用类型化记录，保存正文、附件、引用、模型选择和输入身份；消费队列时，在同一会话事务中删除队列项并增加真实用户消息。

立即补充接管期间保持运行状态，旧请求的正常取消不显示失败或继续入口。用户在交接期间点击停止会终止自动接续，并保留尚未消费的输入；实际保存失败或新请求失败仍显示对应错误。

排队项可编辑、移回输入框或移除。保存失败保留原输入；恢复为草稿后由用户决定重新发送。停止和重启不会自动重放已经保存的业务动作。

聊天默认读取最新一页，页边界包含完整用户及工具调用组。“加载更早消息”继续分页；运行和历史操作通过仓储显式读取完整源。页面窗口与执行历史分开，后台读取全文不会把整个聊天突然展开。

## 通用问答与计划

`ask_user` 适用于任何需要用户补充事实或选择的任务。问题先与调用、运行及数据世代一起保存，再显示交互；回答或跳过先保存，再作为原工具的结果消费一次。停止保留未完成问题，继续时核对原始上下文；更换目标、来源或数据世代会使旧回答失去当前确认效力。

`update_plan` 保存当前轮次的任务进度，在原位置更新。步骤可表示待处理、进行中、完成或阻塞；空列表清除计划。计划说明 Agent 的安排，操作完成依据实际回执。问题数量、答复字数和计划步骤没有固定容量门槛。

## 上下文管理

模型配置保存最大上下文长度、自动压缩开关和触发 Token 数。用户配置优先，其次使用明确模型元数据；已知窗口默认显示 80% 触发点，未知窗口显示未设置。输入区压缩入口与 `/compact` 进入同一原生上下文流程。

当前占用统计包含系统指令、工具定义、消息和附件估算。服务报告值关联产生它的会话与请求；同模型的校准比例只用于后续估算，不把另一会话的实际用量显示成当前请求的报告值。

自动压缩在下一次请求前进行；运行中的手动压缩写入会话控制队列，在完整工具组结束后处理，重启后仍可恢复。成功后消费该控制记录；失败保留错误供显式重试，取消保留已取消状态。当前模型总结较早内容，近期消息及工具配对完整保留。摘要记录来源身份、来源摘要、模型、协议和时间，原始消息继续保存在会话 JSONL 中。保存事务确认后才使用新摘要；取消、来源变化或保存失败不发布失效摘要，同一失败来源不反复自动压缩。编辑重做和模型切换重新核对摘要来源。

空闲时的手动压缩同样进入运行循环。停止、失败或连接变化通过统一收尾将会话与运行记录保存为中断，并记录结算时间；成功后保存完成状态。

## 结果、恢复与协议

业务保存与外部效果分别表达：数据已保存、提醒安排失败、实际通知投递不可观测具有不同含义。普通修改不常驻显示通知投递未知警告。

模型请求和工具尝试记录真实结果与服务用量。普通回复与上下文压缩分别标记请求类型，均计入所属运行；压缩失败或取消时保留服务已经报告的用量。摘要正文不流入聊天，摘要请求的输入用量不替换正常对话的上下文占用。重复用量快照覆盖同一请求，缺失字段保持未知。空正文且没有工具调用的模型终态按回复不完整处理。Chat Completions 与 Responses 使用各自的内容块和续传数据，模型或协议变化后重新组装工作上下文。

HTTP 拒绝、协议错误和服务消息保留具体原因。聊天主界面提供一次错误说明与动作，HTTP 状态、原始响应和操作身份进入技术详情。凭据不进入聊天、工具结果或备份。每次模型请求前检查完整协议历史；工具参数出现当前连接凭据时结束本轮，防止被拒绝的原调用继续进入下一次请求。

重启、显式继续和手动恢复先核对真实未决回执。业务主库把变更与回执一起保存，知识从原生 SQLite 读取同一操作身份，外部效果由其拥有者提供已保存结果。核对成功后补齐原工具结果和轮次归属；结果仍未知时保留待核对状态，旧世代缺少回执不能被认作未执行。核对过程不重复保存、导出或通知，也不发起新的模型请求。

接纳新消息、空闲补充、手动操作卡、压缩或历史修改前使用同一恢复检查。未决操作需要先核对，已有重做批次需要先继续或结束；运行中的普通消息仍按默认行为排队。检查与接纳在同一会话锁内复核。

完整及选择性恢复由各自的恢复 journal 在全部参与者确认后写入本次操作的最终回执。外部协调器读取新账本中的实际记录，核对原操作身份、请求摘要、恢复 ID 和前后世代，再确认完成；普通旧世代回执不能借此重新生效。收尾保存失败时保留 journal，继续恢复完成同一回执，不重复恢复业务对象。

## 存储与平台

每个持久会话使用一份追加式 JSONL，一条记录包含同次相关变化。`conversation-index.sqlite` 保存可重建的列表与消息位置索引；`knowledge.sqlite` 保存知识、版本和真实回执。SQLite 由专属工作线程访问。未发送会话保存在应用内存中，首次接纳时把来源、附件引用、用户消息和运行一起落盘。

Windows 和 Android 使用原生核心。其他平台保留普通功能，Agent 显示暂不可用。旧 Dart 执行核心、Drift 库与 Agent Web worker 已退役；Agent 尚未发布，开发聊天、附件、自定义 Skills 和记忆直接重建。业务、连接和凭据继续由原有领域服务管理。

清空先排空其他执行，关闭原生存储，再由应用删除文件。发起清空的宿主动作持有自己的旧核心，迟到结果不能重开已清空的文件；失败后的恢复重新读取实际存储。
