# 内置 Agent 的运行行为

Agent 由应用拥有，每个会话有独立的执行对象。聊天页面读取同一执行记录的展示视图，关闭页面不会终止已经接纳的保存。

## 执行链与权限

`AgentService` 接收发送、继续、排队消费、补充要求、停止、重生成、历史重做和压缩命令。`RunLoop` 负责请求组装、模型调用、工具调度与结果保存；`InteractionCoordinator` 管理问答和审批；`OperationExecutor` 负责一次业务调用中的领域准备、授权、保存和回执。

模型通过一次业务工具调用完成一次修改，例如 `mutation.apply`、`backups.restore`。宿主生成操作身份，模型不填写或搬运新操作的 `operationId`，公开目录不提供准备后再提交的双调用流程。独立只读调用可并行；有依赖的写入顺序执行，单次批量修改使用一次业务事务。

候选由当前业务调用持有，预览返回、拒绝、完成或失败后立即释放；持久操作记录继续保存实际影响与回执。

- 计划模式返回业务预览。
- 确认模式在当前调用中等待用户决定。
- 完全权限按当前授权执行。

审批描述实际对象和影响。模型参数、Skill 正文和来源资料不能替代宿主许可。未知工具、错误参数和已经变化的资源回送模型纠正；已保存但结果尚未核对的操作进入回执核对流程。

普通任务没有累计 Token、模型轮数、工具次数、强制收尾请求或普通执行时限。用量记录与执行控制分开；用户停止、实际服务终态和真实故障决定运行何时结束。连接诊断保留专用探测行为。

## 输入、队列与会话标题

首条成功接纳的用户输入派生会话标题，手动改名优先；明确交接提供的标题保留。空会话草稿不进入历史。

运行中发送默认进入可见队列。“立即补充当前任务”取消尚未执行的旧步骤，已经接纳的业务写入先完成结果核对。队列项使用类型化记录，保存正文、附件、引用、模型选择和输入身份；消费队列时，在同一会话事务中删除队列项并增加真实用户消息。

排队项可编辑、移回输入框或移除。保存失败保留原输入；恢复为草稿后由用户决定重新发送。停止和重启不会自动重放已经保存的业务动作。

聊天默认读取最新一页，页边界包含完整用户及工具调用组。“加载更早消息”继续分页；运行和历史操作通过仓储显式读取完整源。页面窗口与执行历史分开，后台读取全文不会把整个聊天突然展开。

## 通用问答与计划

`ask_user` 适用于任何需要用户补充事实或选择的任务。问题先与调用、运行及数据世代一起保存，再显示交互；回答或跳过先保存，再作为原工具的结果消费一次。停止保留未完成问题，继续时核对原始上下文；更换目标、来源或数据世代会使旧回答失去当前确认效力。

`update_plan` 保存当前轮次的任务进度，在原位置更新。步骤可表示待处理、进行中、完成或阻塞；空列表清除计划。计划说明 Agent 的安排，操作完成依据实际回执。问题数量、答复字数和计划步骤没有固定容量门槛。

## 上下文管理

模型配置保存最大上下文长度、自动压缩开关和触发 Token 数。用户配置优先，其次使用明确模型元数据；已知窗口默认显示 80% 触发点，未知窗口显示未设置。输入区压缩入口与 `/compact` 使用同一个 `ContextService`。

当前占用统计包含系统指令、工具定义、消息和附件估算。服务报告值关联产生它的会话与请求；同模型的校准比例只用于后续估算，不把另一会话的实际用量显示成当前请求的报告值。

自动压缩在下一次请求前进行；运行中的手动压缩写入会话控制队列，在完整工具组结束后处理，重启后仍可恢复。成功后消费该控制记录；失败保留错误供显式重试，取消保留已取消状态。当前模型总结较早内容，近期消息及工具配对完整保留。摘要记录来源身份、来源摘要、模型、协议和时间，原始消息继续保存在数据库中。保存事务确认后才使用新摘要；取消、来源变化或保存失败不发布失效摘要，同一失败来源不反复自动压缩。编辑重做和模型切换重新核对摘要来源。

空闲时的手动压缩同样进入运行循环。停止、失败或连接变化通过统一收尾将会话与运行记录保存为中断，并记录结算时间；成功后保存完成状态。

## 结果、恢复与协议

业务保存与外部效果分别表达：数据已保存、提醒安排失败、实际通知投递不可观测具有不同含义。普通修改不常驻显示通知投递未知警告。

模型请求和工具尝试记录真实结果与服务用量。普通回复与上下文压缩分别标记请求类型，均计入所属运行；压缩失败或取消时保留服务已经报告的用量。摘要正文不流入聊天，摘要请求的输入用量不替换正常对话的上下文占用。重复用量快照覆盖同一请求，缺失字段保持未知。空正文且没有工具调用的模型终态按回复不完整处理。Chat Completions 与 Responses 使用各自的内容块和续传数据，模型或协议变化后重新组装工作上下文。

HTTP 拒绝、协议错误和服务消息保留具体原因。聊天主界面提供一次错误说明与动作，HTTP 状态、原始响应和操作身份进入技术详情。凭据不进入聊天、工具结果或备份。

重启先核对真实未决回执，不自动执行新模型请求。业务主库把变更与回执一起保存，Agent 库记录对应结果；结果未知时读取原回执，不重复已经保存的操作。

完整及选择性恢复由各自的恢复 journal 在全部参与者确认后写入本次操作的最终回执。外部协调器读取新账本中的实际记录，核对原操作身份、请求摘要、恢复 ID 和前后世代，再确认完成；普通旧世代回执不能借此重新生效。收尾保存失败时保留 journal，继续恢复完成同一回执，不重复恢复业务对象。

## Web 运行文件

Web 的 SQLite 引擎和 worker 随应用发布，使用 [Drift 2.35.3 官方发布](https://github.com/simolus3/drift/releases/tag/drift-2.35.3)中的匹配文件。[官方接入说明](https://drift.simonbinder.eu/platforms/web/)要求把它们放在 Web 根目录，并以 `application/wasm` 提供 Wasm 文件。

| 文件 | 字节数 | SHA-256 |
| --- | ---: | --- |
| `web/sqlite3.wasm` | 758619 | `efd308be92a34f3aa15f289a37f213b0230fd80888a1364326ee29579d892d37` |
| `web/drift_worker.js` | 361829 | `a54b81412d4c4ab56653bb9e4c02912b0820bb37e2bba00722ddef4d78083d4a` |

当前保存的是官方预构建 worker。需要按锁定依赖重建时，使用仓库源码入口：

```sh
dart compile js -O4 --no-source-maps tool/drift_worker.dart -o web/drift_worker.js
```

重建或升级依赖时同步更新产物来源、摘要和浏览器验证。浏览器使用可用的持久 SQLite 实现；无法提供持久存储时明确报告错误，不把纯内存数据库当作保存成功。浏览器测试工厂显式选择内存库，避免触及实际站点数据。

## 存储与验证

会话、消息、工具调用、操作投影、队列、摘要、历史版本与知识内容在共享的 Drift/SQLite Agent 库中按行保存；原生数据库运行于后台 isolate，二进制附件独立保存。切换时重建 Agent 数据，旧双槽存档仅用于核对原有操作的未决证据。课表、日程、连接、凭据和用户设置由原领域服务保留。

切换时，知识写入使用旧知识文件中的操作回执核对，聊天修改使用旧会话快照核对；空的新数据库不能证明旧副作用是否完成。核对只更新主库回执，不再次执行已接纳的写入。缺失真实证据时，在 SQLite 中保存原操作身份与未决记录并保留旧 JSON 文件，新 Agent 和无关业务继续使用。后续显式回读或重启继续核对这些原操作；全部核对后清理旧 JSON。旧附件在首次切换返回前清理，延后的退休流程保留新 Agent 已保存的附件。真实文件读取和已接纳的业务逆操作失败继续由恢复入口报告。对应回归见[旧知识保存后回包丢失](../test/agent/store/legacy_agent_recovery_test.dart)。
