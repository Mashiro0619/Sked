# Agent 模型与思考强度

Sked 使用一个 API 连接，可以启用多个模型。获取模型目录后勾选需要的模型，也可手动添加模型 ID；目录只表示服务返回了这些名称，不证明账号能调用或模型支持某种思考档位。连接可以先保存，再获取目录。

模型清单与默认模型一起校验。清空清单会清除默认选择但保留连接；同时提交空清单和非空默认 ID 属于冲突配置，整体拒绝，不忽略其中一项。

设置目录将 `agent.models` 描述为结构化对象列表，并指向 `connection.prepare`。通用设置修改和重置不能绕过连接适配器对模型清单、默认选择及凭据目的地的共同校验。

用户界面、会话工具和学校网页交接新建会话时保存当时的默认模型及思考强度；之后更改默认值不会改变已有会话。模型尚未配置时创建的会话和旧档缺失的选择保持未指定，首次发送时使用当时默认值并保存。每个模型分别配置可选思考强度及默认值；“自动”始终可用，表示不发送思考参数。Chat Completions 使用 `reasoning_effort`，Responses 使用 `reasoning.effort`。选中的参数被服务拒绝时报告请求失败，不悄悄移除参数或换模型重试。

会话分别保存自己的模型和强度。用户发送或追加到队列时固定选择，整个模型与工具循环使用同一快照。修改会话选择、默认模型或可用清单不会中止已经开始的运行；关闭功能、改变端点或凭据仍会停止后续步骤。HTTP 传输同意继续绑定实际运行使用的端点、凭据、协议和模型，不因调整其他会话的模型而失效。

已经停用的模型或思考档位不会被自动替换。待处理输入保留原选择并等待用户重新选择；选择后只修复无法使用的队列项，用户通过“继续”启动，不自动发送。仍有效的排队输入保持提交时的选择。

每次运行保存模型、协议和思考强度；助手消息保存产生其协议续传内容的模型与协议来源。切换模型后，普通消息及工具结果继续可用，旧模型的 opaque reasoning／续传字段不会交给新模型。构建请求时只有模型与协议均一致的续传内容可以复用，没有来源信息的旧续传字段只作历史保存；更换协议仍需满足会话原有的连接目的地核验。

`AgentSettings.model` 保留为默认模型 ID，`models` 保存模型与档位清单；旧单模型配置读取为一个仅含“自动”的模型。模型选择从会话档案 v3 起保存，后续格式继续兼容 v1 和 v2；历史缺失的模型用量或强度信息不补造。当前会话格式见[运行时](AGENT_RUNTIME.md)，升级主库与默认启用的规则见使用逻辑和主库迁移。

回归覆盖单 API 多模型保存、合法档位组合、发送与排队时冻结、活动运行中移除模型、显式修复队列、多会话隔离、跨模型续传处理及两种协议的参数编码。真实模型是否支持所选档位须另行联调。
