# Windows 原生行为与验收

## 通知正文与动作

点击课程或日程通知正文，应先选中对应工作区及日期，再打开仍然有效的目标详情。运行中点击与完全退出后的通知启动遵守同一规则。

Windows 通知插件可能把带 `launch` 参数的正文点击报告为 `selectedNotificationAction`。网关先识别 Sked 的动作包装；若不是动作包装，只有有效的 `sked.agenda.v1:` 正文载荷才能进入导航。损坏的载荷、未知动作版本及关闭通知不触发导航；“稍后”和“已处理”仍交给动作处理器。路由器继续校验目标与当前数据，并过滤重复回调。

验收必须使用独立 MSIX 身份、激活 GUID、合成数据目录、通知 ID 与运行时锁，不应复用真实 Sked 数据、通知或注册表项。分别记录运行中与冷启动的原生回调类型、网关分派、目标工作区/日期和详情可见性；仅有插件注册成功或替身回调不算 Windows 点击验收通过。

## 窗口位置与状态

窗口记住上次的位置、大小及最大化状态。最小化时关闭，下次正常显示，并保留最小化前是否最大化。保存和恢复均使用 Windows 的窗口放置坐标，避免再次按 DPI 缩放；第一帧完成前恢复几何而保持隐藏。

窗口拖动或缩放结束、显示状态变化及关闭时保存。注册表不可读写、记录损坏、或保存位置所在显示器已移除时，保留可见的默认启动位置，不阻止启动。

原生自动验证可在 CMake 中启用 `SKED_BUILD_WINDOWS_RUNNER_TESTS` 并运行 `sked_window_placement_tests`。该测试只操作按进程 ID 隔离的注册表键和自建窗口。完整测试应用构建必须同时设置 `SKED_WINDOWS_TEST_NAMESPACE`，使其窗口状态与后续实例通知空间独立于生产应用。

## 再次启动

同一 Windows 会话再次普通启动 Sked 时，原生进程先查找持有命名互斥量的窗口，恢复最小化状态并请求把它带到前台，然后退出第二个进程。窗口尚未注册时短暂等待；原进程已退出或崩溃时重新接管互斥量。Windows 拒绝前台请求时通过任务栏提示，不使用强制焦点劫持。

Dart 层的数据实例租约保持不变，仍负责保护实际数据。通知 COM 服务的启动参数本身不包含通知正文；此类启动保留插件接收真正激活回调的路径，不能把尚未收到载荷的进程当作普通双开直接丢弃。

`sked_single_instance_tests` 使用按 PID 隔离的命名空间和真实子进程，验证第二实例退出、窗口恢复/前台激活、启动竞争、COM 回调入口保留，以及崩溃后接管。

## 窗口拖拽

Flutter 请求开始原生拖拽时，使用 `GetCursorPos` 取得当前光标位置，并在释放捕获后发出标题栏拖动请求；不使用此前出队消息的位置。无法读取光标或目标窗口无效时不发起拖拽。`sked_native_window_drag_tests` 在自建窗口中截取这条真实 Win32 消息，验证坐标、标题栏命中及捕获释放顺序，不注入鼠标输入。
