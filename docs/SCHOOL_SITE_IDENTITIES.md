# 学校站点的持久身份

每个已保存的学校站点拥有独立 `id`。修改名称或登录地址保留 ID，新建和复制分配新 ID；名称、URL 和列表位置都不是对象身份。两个站点可以具有相同名称或登录地址，编辑其中一个不会修改另一个。

站点本地存储使用 `school-site-storage` v2。v2 要求每项 ID 非空、格式合法且在整份列表中唯一，缺失、冲突或不合法时整份拒绝。遇到高于当前版本的存储继续阻断回退和写入，不能由旧逻辑静默丢弃身份。

原始列表与 v1 仍可读取。纯解码保留缺失 ID 的旧对象；学校站点服务在现有串行恢复边界内一次性分配 ID，经原事务存储保存 v2 成功后才提供可写列表。迁移保存失败时保留原快照并阻断写入，后续重新加载核对存储；没有成功持久化的候选身份不作为备份目标。空的旧列表没有待分配对象，下一次保存会使用 v2。

内置站点在资产中显式登记固定 ID，后续改名、改 URL 或调整顺序不得更改它。恢复内置内容采用发布版本的 ID，不根据名称或地址生成。当前内置列表为空，新增资产条目时同样遵循此规则。

## 导入、导出与工具

便携站点 JSON 继续使用列表格式，已保存对象的导出携带 ID。无 ID 的旧导入在具体导入预览中分配新身份；同一预览及其重试复用这份映射。带 ID 的导入保留已有身份；重复的显式 ID 或不合法 ID 整份拒绝，不能按同名自动合并。

追加导入不会覆盖当前站点。导入 ID 与现存对象冲突时，为追加副本分配新 ID；整表替换保留导入 ID。站点页面已有的“合并”入口继续仅去除名称与 URL 都完全相同的内容，Agent 的显式追加仍允许相同内容的多项。可选备份的对象匹配使用持久 ID；其调用者须在预览及恢复日志中固定旧备份的新身份映射，不以名称或 URL 寻找替换目标。

兼容的整包恢复同样在写入准备日志前固定站点身份。升级后读取到尚未完成、站点缺少 ID 的旧恢复日志时，先持久保存该次分配的映射并读回核对，再写主库和站点；中断后继续沿用同一映射，不因重试创建新身份。

`school_sites.list/get` 返回 ID 和绑定当前版本的 `handle`。编辑、删除仍需该句柄，不能用 ID 绕过来源版本校验；名称与 URL 是可配置字段，ID 不属于 `school_sites.prepare` 的任意可写字段。新回执比较完整 ID、名称和 URL；旧回执缺少 ID 时继续按其原来的完整有序内容核对。
