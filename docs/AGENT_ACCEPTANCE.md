# Agent 通用能力验收

本协议用于验收默认 Agent 的文件、网页、Python、Office、业务保存和结果交付。每次执行固定源码与实际安装包，按平台记录结果。实现进度见[插件架构](AGENT_PLUGIN_ARCHITECTURE.md)，分发要求见[发布验收](RELEASE_ACCEPTANCE.md)。

当前开发检查采用格式检查、静态分析和源码审查，不编写或运行自动化测试；真实模型调用与性能采样继续暂停。Windows 原生编译已因调试启动故障排查单独恢复。以下完整平台与任务流程在相应验收恢复后执行，逐项记录通过、失败、受阻或未执行。

## 准备与记录

使用单独的验收课表、日历、文档与保存目录。开发机脚本、日志、截图、导出副本和测试数据放在 F 盘；设备上的应用文件沿用平台存储。保留原输入及预期结果，便于核对实际读取、修改和保存的内容。

每轮记录以下信息，模型、输入或包发生变化后另开一轮：

| 字段 | 内容 |
| --- | --- |
| 源码和包 | Git SHA、应用版本、构建号、分发渠道、包名及 SHA-256、签名摘要 |
| 环境 | 日期、执行人、系统版本、设备／ROM、ABI、工具链；注明实体设备、模拟器或桌面原生环境 |
| 连接与权限 | 模型、协议、端点类别、上下文配置、Agent 权限模式及系统文件授权状态；不记录凭据 |
| 输入 | 原文件及摘要、网页地址、验收业务对象、已有内容与预期变更 |
| 执行 | 命令或界面步骤、实际工具调用、审批选择、停止或故障发生位置 |
| 结果 | 实际对象、文件位置和摘要、来源与日期、原回执状态、重开后的结果 |
| 证据和遗留项 | 日志／截图位置、实际覆盖范围、失败原因及下一步；性能数据单独记录采样协议 |

## 安装包与执行环境

| 平台 | 检查步骤与完成条件 |
| --- | --- |
| Windows | 从最终分发目录启动 `lib/main.dart` 对应的正式入口，核对 Rust 原生库及 `data/python` 中的 CPython 和依赖。使用没有另装 Python 的干净用户环境执行文档任务，确认运行的是随包环境。普通包与 Store 包按各自实际分发形式记录。 |
| Android | 核对 `armeabi-v7a`、`arm64-v8a`、`x86_64` 包内容；分别在匹配的运行环境启动，记录当前进程位数及实际 Python ABI。批准执行后由专用 Service 启动解释器，等待子进程、输出和回执收尾；停止后可接纳下一任务。 |
| Office 依赖 | 在两端使用随包 python-docx、openpyxl、python-pptx 完成读取、创建和修改，核对依赖版本与[运行时清单](../tool/python/runtime.json)。用户执行时不安装依赖。 |
| 系统文件访问 | Windows 使用当前用户权限，分别检查普通路径和实际可用的 UNC 位置。Android 检查所有文件访问、普通路径、文档 URI、目录树授权以及撤销后重新选择；按实际系统版本记录旧版存储权限路径。 |

Android 各渠道使用相同的文件权限方案；Google Play 的所有文件访问权限审核和材料要求在提交前完成。安装、升级与系统交互继续遵循[发布验收](RELEASE_ACCEPTANCE.md)和[可靠性指南](RELIABILITY_BASELINE.md)。

## 通用任务

Windows 和 Android 各完成以下三个任务，再完成一个不同的组合任务。使用正式聊天入口，由 Agent 自主选择工具；保存后从业务界面或系统应用重新打开结果。

| 任务 | 输入和步骤 | 完成条件 |
| --- | --- | --- |
| 考试与复习计划 | 提供考试安排，并故意缺少一项影响安排的信息；回答 Agent 的澄清问题，让它结合已有课程和日程规划复习并保存。 | 问题与答复随原调用保存；计划符合补充信息和既有时间安排；日程实际存在，日期、时间、所属日历及重复规则正确。 |
| 学校通知 | 提供公开通知入口，让 Agent 继续读取相关链接及附件，整理有关事项，并按要求加入日程。 | 结论能对应原文；显示实际来源，发布日期与获取时间分开；缺失日期不补造；日程与原通知内容一致。 |
| 文件夹资料与笔记 | 指定平台允许访问的资料目录及保存位置，让 Agent 浏览、读取多份文件并生成笔记和文字行动清单。目录通过文件工具定位；桌面拖入目录当前会被拒绝。 | 覆盖用户指定资料；笔记与行动清单写入指定位置，可用外部应用打开；交付记录保留真实文件名和位置。行动清单作为文件或文字内容交付。 |
| 不同的组合任务 | 例如比较两份文档后更新指定文件，或整理工作簿数据并生成另一份结果。 | 通过同一组工具完成新的组合，核对差异、修改与实际产物；Agent 主循环无需新增该任务的专用分支。 |

## Office 与模型内容

对 DOCX、XLSX、PPTX 分别覆盖两种输入：直接发送聊天附件；通过 `files.read` 或 `web.fetch` 保存文件后，把 `contentId` 交给 `office.read`。读取完成后继续提问文件中的具体事实，核对实际进入模型的正文及媒体内容。

| 格式／内容 | 必须核对 |
| --- | --- |
| DOCX | 正文、表格、页眉页脚和嵌图；带删除／移出修订的旧文字不混入正文，修订索引仍保留这些文字。 |
| XLSX | 工作表、实际单元格、公式与已有缓存值分别读取；修改后保留需要的公式，重新打开核对目标单元格。读取器不执行公式重算。 |
| PPTX | 幻灯片顺序、组合形状、表格、备注、图表和嵌图关系；创建或修改后用演示文稿应用重新打开。 |
| 长输出 | 首次正文页与 `content.read` 后续页连续，后续事实来自完整保存的结构内容。 |
| 图片及原生文件 | 支持的 PNG、JPEG、GIF、WebP 嵌图以实际字节发送；PDF 和 Office 原生输入按当前模型协议的实际支持核对。协议不支持 Office 原生输入时，Agent 可通过固定读取器取得正文。 |

创建、修改通过 `python.execute` 使用冻结的完整输入；`publish` 登记实际存在的文件。核对读取内容、脚本结果、登记文件和外部应用打开后的内容一致。页面渲染、公式重算和 PDF 导出仍是后续能力，不列为本轮随包文档库的完成条件。详细行为见[办公文档](AGENT_OFFICE.md)。

## 权限、失败与停止

分别用三种权限执行一次固定文档读取和一次有明确输出的脚本／文件写入：计划模式可运行固定读取器，写入与任意脚本只展示预览；确认模式由允许／拒绝控制这一份材料；完全权限通过相同接纳检查后执行。修改代码、输入、工作目录或权限后，旧许可不适用于新材料。

在验收数据上覆盖以下情况，并核对即时界面、技术回执及重开后的记录：

- 拒绝修改、接纳前取消、执行中停止，以及已经登记文件后停止。明确未启动时显示“未开始”，其他取消显示“已取消”，已登记文件仍保留。
- 读取后由外部程序修改源文件，再请求版本保护写入，确认冲突保留实际源文件与可用恢复位置。
- Android 授权撤销、文件移走、网络失败及没有文件查看器，错误能对应当前动作，已有结果继续保留。
- 脚本非零退出、输出保存失败，以及运行中断后结果仍未知。失败或待核对状态与可观察文件效果分别保留。
- 准备、执行或保存期间关闭页面、切换会话、停用 Agent 或退出应用。已接纳工作由原实例收尾，旧页面与菜单不改绑新结果。

## 交付、重开与备份

文件与网页来源直接显示在对应操作下，业务对象沿用操作回执的查看入口，完整代码与回执可展开。按[结果交付](AGENT_DELIVERY.md)核对以下动作：

1. Windows 打开、定位、复制真实位置；Android 普通路径打开查看副本，文档 URI 向查看器授予临时读取权限。
2. 恢复文件按原名称和类型打开查看副本，复制与定位仍指向恢复原件；同一文件登记多个位置时，各行保留自己的路径。
3. 网页打开实际来源，重定向保留原始与最终地址；网站日期和本次获取时间分别显示。
4. 切换会话、重新启动及上下文压缩后，内容与交付记录可从原消息重建。再次读取外部文件才取得新的内容版本。
5. 导出并导入聊天，分别覆盖携带附件和不携带附件的选择。正文及实际携带的文件按备份规则恢复，缺失附件明确显示缺失；外部文件本体另行保存。
6. 导入的旧文件位置可查看、复制，不能直接作为本机文件打开或定位；导入后的新任务产物正常提供本机动作。旧运行、审批和队列不重放。
7. 重开后先核对原操作身份和持久回执。已保存日程不重复创建，未知执行不自动重跑；无法核对的结果继续显示待核对。

## 既有会话与桌面交互

继续覆盖多会话、排队输入、立即补充、问答与计划、手动／自动压缩、附件、Skills、历史编辑重做、重新生成和自动标题。通过[运行行为](AGENT_RUNTIME.md)、[历史](AGENT_HISTORY.md)与[对话界面](AGENT_CHAT_DESIGN.md)核对目标、权限、保存和原消息归属。

Windows 原生鼠标与键盘按[桌面交互计划](DESKTOP_INTERACTION_PLAN.md)检查对象右键、菜单键／Shift+F10、区域快捷键、文本编辑、文件拖入、截图粘贴及文件动作。保留输入法合成、窄屏操作行、菜单焦点、窗口缩放、大字号、DPI 和保存后关窗行为；会话或数据来源失效后，旧菜单和隐藏区域不接收动作。D9 列表多选仍是后续增强。

## 完成判定

每个平台分别记录实际通过的项目和剩余问题。发布前使用最终候选包核对本协议及[发布验收](RELEASE_ACCEPTANCE.md)的适用项目，修复后重查受影响流程。真实模型质量、调用成本和性能使用各自的实际记录；历史迁移验收按当时源码与包保留。
