## 本轮检查发现与处理

- MSIX 测试夹具在 Windows PowerShell 5.1 下只加载了 `System.IO.Compression.FileSystem`，解析 `ZipArchiveMode` 前缺少其程序集，导致 15 项失败。现已显式加载 `System.IO.Compression`，并新增强制使用 Windows PowerShell 的回归；最终整组和完整测试均重新通过。没有改为跳过这些失败。
- 本机共享 Flutter 构建资产中残留了 2026-09-26 的 Debug `kernel_blob.bin`（134,144,064 字节），首次 Release 构建把它复制到了输出目录。对照当前 Flutter SDK 的 AOT 规则、文件时间与摘要后，先备份，再只移除两个已核实的生成文件并重新执行 Release 构建；最终候选 ZIP 不含该调试内核。没有执行会清空全部候选包的 `flutter clean`。
- Windows 构建仍有第三方 WebView 插件的既有 CMake／MSVC 告警；“构建通过”不表示本轮消除了这些告警。没有把开发机上的构建检查写成干净用户环境的运行验收。

## 可复现的主要命令

从仓库根目录运行，先确认 Flutter 版本与工作区状态：

```powershell
git status --short
flutter --version
flutter pub get --enforce-lockfile
Push-Location packages/android_productivity_plugin
flutter pub get --enforce-lockfile
Pop-Location
flutter gen-l10n
git diff --exit-code -- lib/l10n/
dart format --output=none --set-exit-if-changed .
flutter analyze --no-pub
flutter test --no-pub --coverage
flutter build apk --release
flutter build apk --release --split-per-abi
flutter build windows --release --dart-define=SKED_MICROSOFT_STORE_ID=
```

每一步须检查退出码；本段用于列出命令，不是忽略中间失败的自动发布脚本。Android 使用本机已有签名配置，禁止用 CI 临时签名 APK 充当正式候选包。Release 构建保留默认依赖／插件准备步骤，不用 `--no-pub` 复用可能属于 Debug／integration_test 的插件注册表。切换 Store／站外渠道必须重新编译，不能只更换清单或重命名旧产物。
