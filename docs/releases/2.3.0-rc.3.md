# Sked v2.3.0-rc.3

2.3.0 第三个候选版，集中改进桌面布局与编辑、重复日程和提醒，并完成课表、日程及共享流程的重构和性能优化。本次 RC 重点验证实际覆盖升级、旧数据恢复、系统通知与日常交互。

> **升级前请导出并独立保留完整应用备份和旧版安装包。** AppData 顶层仍为 v4，但日程格式已升级；新版保存的数据不能直接交回 RC.2 读取，回退需使用升级前备份。

## 桌面布局与编辑

- **常用区域可调整并记住尺寸**：资源栏、安排栏、设置导航、主题预览、导入预览和学校站点分栏可拖拽调宽，月历议程与全天日程区域可调整尺寸。重启恢复手动选择的尺寸，窄窗和大字号下仍按可用空间显示。
- **浮窗可拖动、缩放**：课程／日程编辑、详情、提醒与分类等面板支持从边缘调整尺寸，也可使用键盘调整。缩放不占用正文滚动条，调整窗口时保留草稿和滚动位置。
- **编辑表单更紧凑**：突出课程／日程标题，按实际空间排列地点、分类、日期、时间、周次和节次，将补充内容收进「更多」。标题、滚动正文和底部操作区统一，窄窗和大字号自动换行。
- **任务跟随实际入口**：编辑与选择面板贴近触发控件打开，嵌套任务保留入口位置。保存完成只关闭所属页面，不误关后来打开的任务；编辑期间仍可拖动应用顶栏移动窗口。
- **节次时间集管理更明确**：课表绑定与共享资源管理分开，没有时间集时可直接新建；正在使用的时间集不能删除。切换或返回前等待保存或退出确认，保留未完成的编辑。

## 日程、重复规则与提醒

- **明确重复日程的编辑范围**：可选择「仅本次」「本次及以后」或「整个系列」。单次修改与拆分后的系列独立存在，范围外的日程和已处理提醒保持原状；月末重复继续遵循原始日期。
- **提醒可跟随默认或单独设置**：新增「跟随默认」「关闭」「自定义」三种策略，新建日程默认跟随通知设置，旧记录保留原有含义。调整默认值不会覆盖正在编辑的自定义草稿。
- **隐藏分类的提醒可单独选择**：「隐藏日程分类后仍提醒」默认关闭；开启后允许该分类的应用内提醒和系统通知，普通日历仍保持隐藏。系统通知继续受总开关、权限和工作区状态控制。
- **日历和文件交换更准确**：月视图、周视图与侧栏统一从周一开始；修复部分夏令时日期的跨日事件遗漏。JSON 保留提醒策略与月末重复日期，ICS 改进重复例外、次数限制和本地／UTC 时间的往返处理。

## 响应速度与稳定性

- **减少重复工作**：课表、日程、设置、存储和通知按职责更新，减少无关页面重建与提醒重排。长日程列表按可见条目构建，日期分组、月页、周视图和课程排版复用已有结果。
- **大文件处理移到后台**：原生端在后台处理存档编解码与导入预处理，预览确认复用解析结果，保留数据校验、失败回滚和重试草稿。
- **保留编辑与导入结果**：学校导入校对表单与 JSON 同步，保存失败可原地重试；明确周次不会误变为每周课程，缩短学期时先提示并保留原周次。课程未编辑的结构化自定义字段保留原始内容与类型。
- **完善交互细节**：修复短窗、横屏键盘、大字号和窄课程卡片的溢出与裁字，改善文字、图标和焦点对比度。手机拖拽关闭弹窗仍经过草稿确认；Android 过期文件／授权回调不会影响新请求。
- **修复 Windows 辅助技术交互**：改善悬停提示、工作区画布与设置滑块的语义节点稳定性，保留日期标题、保存反馈和课程键盘操作。

性能改进来自整组数据与渲染优化。课程极密时，课表切换和视图重建仍可能出现停顿；本次候选版继续收集真实设备上的日常使用反馈。

## 更新提示与渠道

- 完成隐私同意和首次引导后，每次启动自动检查一次更新。编辑、查看详情、其他弹窗打开或应用失焦时，只更新设置中的版本标记；启动检查失败保持安静。
- 更新弹窗使用更紧凑的版本信息和 Markdown 日志，长内容独立滚动，检查或打开入口失败时可重试。所有渠道共用版本检查，更新按钮按安装来源打开 GitHub、Google Play 或微软商店。
- 「接收预发布更新」在新安装时默认开启，已有选择继续保留。开启该选项不等于加入商店测试渠道，商店提供的版本可能晚于 GitHub。

## 升级与回退

- AppData 顶层保持 **v4**，通用日程格式从 RC.2 的 **schema 5 升至 6**。RC.3 可读取旧数据；RC.2 不支持新版日程数据及包含它的备份。需要回退时，使用升级前保存的备份，保留新版期间新增的数据副本。
- 普通备份不包含 API Key；桌面区域尺寸仅保存在本机，不随备份迁移。恢复期间会暂停并发修改，失败后可重试；正常升级不需要先清空现有数据。
- ICS 不交换提醒设置。完整迁移使用应用备份；日程 JSON 保留各日程的提醒策略，但「跟随默认」会使用接收设备的设置。
- 覆盖安装沿用相同渠道、包类型和签名。Windows 便携版需解压完整目录；微软商店版与站外版不保证直接覆盖或自动迁移。Android 分架构 APK 与通用 APK 的版本规则不同，升级时应保持原包类型。
