# Agent 二进制附件

附件选择不限制扩展名。文件先复制到应用自己的存储并读回核验，再把文件名、媒体类型、字节数、SHA-256 和稳定 ID 保存到会话。原路径和二进制正文不进入聊天 JSON。每份文件上限为 32 MB，一条消息最多 20 份；一份请求的二进制内容合计最多 48 MB。这里的 MB 为十进制字节，不沿用旧文本来源的 512 KiB 预算。

## 发送与历史

已保存的待发送文件属于会话草稿，切换页面后继续保留。发送或追加待处理输入时，文件引用与对应用户消息一起保存，再从草稿中移除；支持正文为空的附件消息。保存失败不宣称引用已落盘，同一次本地重试复用已经核验的文件身份。停止文件复制或请求编码会取消后续读取，已经发布的草稿和历史引用仍保留。

重试会重新核验已经保存的文件，显示实际保存状态并继续支持取消；成功后恢复为本地已保存状态，复用同一文件身份。重试核验尚未完成时不能发布引用，取消或失败不删除已有历史引用。

当前请求的附件在每一轮模型和工具往返中完整发送，不因文本上下文压缩而退化为文件名。以后的新请求默认不重复发送旧文件，并在上下文中说明旧文件没有纳入；用户可以把历史中的本地文件重新附加到下一条消息。复用只增加引用，不复制二进制。删除草稿附件不会删除仍被消息引用的内容；删除聊天或清理历史之后，只有最后一个引用已经消失的内容才可以回收。

文件仍在本机保存、正在编码、正在发送、服务已接受以及发送失败分别记录。编码进度按实际处理的文件字节数报告；HTTP 客户端没有可靠的逐字节上传回调，因此发送阶段使用不定进度，不冒充模型读取进度。收到成功 HTTP 响应表示服务接受了请求，不能证明模型已理解附件。请求被拒绝时保留文件，显式继续使用原消息和附件，不自动换模型或重复追加用户消息。

进程中断后，尚处于编码或发送中的历史记录转为结果未知；加载会话不会自动发送。缺失或摘要不一致的历史文件明确拒绝发送，不访问原设备路径，也不只发送文件名。文件已成功保存到会话之后可跨重启读取；尚未成功发布引用的本进程重试缓冲不等同于已经保存的草稿。

## 原生协议

兼容接口按照其内容块表达文件，不提供 OCR、音频转码或视频抽帧。目录中的模型名称不代表具体账号拥有相应能力，服务仍可能拒绝某种输入。

| 内容 | Chat Completions | Responses |
| --- | --- | --- |
| PNG、JPEG、WebP、GIF | `image_url` 数据 URL | `input_image` 数据 URL |
| WAV、MP3 | `input_audio` 原始 Base64 与格式 | 当前文件链路没有相应内容块，拒绝发送 |
| PDF | `file` 内容块 | `input_file` 内容块 |
| 已登记的文本、代码、ICS、TSV 和 Office 文件 | 当前原生 `file` 路径不支持，拒绝发送 | `input_file` 内容块 |
| 其他文件及视频 | 保存本地后说明当前协议不支持 | 保存本地后说明当前协议不支持 |

映射依据：[官方文件输入](https://developers.openai.com/api/docs/guides/file-inputs)、[图像输入](https://developers.openai.com/api/docs/guides/images-vision)和[Chat Completions 音频输入](https://developers.openai.com/api/docs/guides/audio-chat-completions)。Responses 的官方扩展名与 MIME 类型由[文件类型目录](../lib/agent/attachments/attachment_media_types.dart)统一登记，具体内容块由[协议编码](../lib/agent/provider/provider_protocol.dart)生成。旧附件保存为泛型 MIME 时，仅在请求中按该目录规范类型，文件字节、摘要和已保存引用保持原值；增加支持时须核对协议并补回归。

请求在读取文件前先核算声明字节数、Base64 膨胀量和 JSON 开销。文本及工具 JSON 预算与原始文件预算独立；取消信号和总超时在文件读取前建立，读取与编码分块执行。实际字节数和摘要核验完成之后才交给 HTTP 客户端；重定向继续被禁止。

## 存储与维护

原生附件位于应用支持目录的 `Sked_agent_attachments`，文件名使用稳定 ID；写入中的 `.pending` 文件也纳入清空及无引用回收。Web 使用独立 IndexedDB 数据库的原生 Blob，不把 Base64 塞进 SharedPreferences。会话格式 v4 保存附件引用，继续读取 v1–v3；旧格式没有的附件信息不补造。

附件服务将本地复制、引用发布与垃圾回收串行化。取消一直覆盖到引用提交前的最后一次读回核验；已经提交的引用以实际保存结果为准。清空和恢复先停止新导入，取消复制与核验读取，再排空已接受的引用写入并冻结会话；失败后必须按宿主维护协议重新核对存储。可选备份的二进制归档及历史版本引用由各自拥有者接入同一引用管理，不能只备份聊天 JSON 就宣称已经携带文件。
