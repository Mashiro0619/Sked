# Agent 附件

附件先保存到应用私有存储，长度和 SHA-256 核对成功后发布引用。Rust 在同一存储队列中完成文件入库、元数据与草稿引用发布；会话 JSONL 保存稳定 ID、名称、媒体类型、长度和摘要，二进制按摘要独立保存。选择文件不自动调用模型，也不自动导入课表或日程。

## 草稿、队列与历史

任意扩展名的文件均可加入本地附件；是否能发送由实际协议和模型能力决定。文件大小、单条消息附件数量及整次请求附件总量没有 Sked 固定额度。

新会话尚未接纳输入时，草稿引用属于当前应用生命周期，不建立历史记录；首次接纳输入时与用户消息一起保存。已有持久会话的草稿和排队项保留各自引用。队列消费把完整输入和文件引用一起移入用户消息。

移除草稿中的文件不会删除仍被其他消息、队列或历史版本引用的内容。Rust 垃圾回收读取全部会话 JSONL、历史版本、队列及当前草稿引用，不依赖页面是否加载了旧聊天。文件复制成功与引用发布之间不会插入回收。

文件选择结果先分块暂存到当前导入拥有的临时目录；重试复用稳定的导入身份与输入文件。输入边界从原生会话状态读取，原请求位于更早消息页时仍绑定同一输入。取消绑定本次导入，Rust 在提交前检查取消并返回实际结果；已提交的引用保持成功状态。保存失败不宣称引用已发布，迟到的选择结果仍须属于原会话、运行和输入边界。

桌面聊天输入区可拖入一个或多个文件，实际命中的可用输入区显示落点提示。整批文件固定拖入时的会话、数据世代、运行与原生输入身份，按顺序进入同一附件保存链；处理期间可以取消，失败或取消后可重试剩余文件，已保存附件保持成功。打开模型等菜单保留批次，切换会话、隐藏宿主或输入边界失效后结束旧批次。添加后保留为草稿，由用户发送。当前拖入入口不接纳文件夹，目录引用随通用文件 Provider 接入。

桌面输入区的标准粘贴快捷键按剪贴板文件列表、图片、文本选择一种内容。文件列表进入同一附件批次，截图转为 PNG 并保留文件名；纯文本通过文本编辑动作插入，保留撤销和选择行为。读取期间固定原输入焦点、会话与数据世代，来源、输入边界或可写状态失效后结束读取；读取完成前暂停发送和添加文件。失败后可再次粘贴。macOS 只接受本地文件 URL 并在读取期间使用对应系统授权；文本选择工具栏沿用普通文本粘贴。

## 流式处理与展示

原生文件分块读取、复制和编码，上传使用流式请求体。进度对应已经处理的实际字节；发送阶段只表达客户端能够观测的状态。成功 HTTP 响应表示服务接纳了请求，不表示模型已经理解文件。

附件显示紧凑缩略图或文件条目，支持预览、移除和取消。长名称通过提示、预览和读屏提供完整内容。预览只读取用户选择的本地私有文件；切换会话或关闭所属宿主后，旧读取和迟到回调不能操作新的页面。

桌面附件整行支持右键，焦点位于附件操作控件时可用菜单键或 Shift+F10 打开同一组动作，提供移除入口的附件也可用 Delete 移除。菜单与原按钮共用预览、再次附加和移除入口，按当前附件实际支持的操作显示；目标绑定会话、文件元数据和所属输入，切换会话、文件变化或宿主失效后旧菜单失效。预览正文继续使用原有文本选择菜单。

桌面私有附件还支持打开文件、在文件夹中显示、复制路径和另存副本。前三级动作使用应用系统临时目录中按原名生成的独立副本；另存副本将核验内容保存到所选位置。副本分块核对长度与 SHA-256，复用前再次核验；外部编辑后的旧副本保留，下次从附件原件生成新的副本。外部编辑不会改写聊天中的原附件。操作菜单同时绑定 Reader 数据世代，来源变化后旧菜单失效；复制取消和维护等待读写句柄关闭，失败副本随后清理。成功副本保留供系统程序使用，长期保留请另存到用户目录。

停止会取消尚未完成的复制、核验、编码和传输。已经保存的引用保留。缺失文件、长度变化、摘要变化和协议不支持分别报告实际原因，保持原消息可重试。

## 模型协议

附件由当前协议的原生内容块发送，不自动进行 OCR、音频转码或视频抽帧。

| 内容 | Chat Completions | Responses |
| --- | --- | --- |
| 已登记图像 | `image_url` 数据 URL | `input_image` 数据 URL |
| WAV、MP3 | `input_audio` | 当前附件链路报告不支持 |
| PDF | `file` | `input_file` |
| 文件目录中登记的文本与文档 | 按当前 `file` 能力检查 | `input_file` |
| 其他类型 | 保留本地文件并说明实际能力 | 保留本地文件并说明实际能力 |

精确类型以[媒体类型目录](../lib/agent/attachments/attachment_media_types.dart)、[Rust 类型目录](../rust/src/runtime/attachment_media.rs)和[原生传输准备](../rust/src/runtime/transport.rs)为准。Rig 内容块保留私有附件 ID；HTTP 传输在发送前打开相应文件，按原始媒体类型和文件名生成请求内容，分块 Base64 编码并核对实际长度、SHA-256。JSONL 不嵌入二进制内容。服务拒绝后不自动换模型或只发送文件名。

活动上下文保留文件引用。压缩不会删除原文件；重新生成使用所选回复之前的有效附件。仅由退役历史版本引用的文件不会自动进入当前模型请求。

## 平台与维护

原生二进制位于 Agent 数据目录的 `attachments` 子目录，采用摘要命名的 `.blob` 文件。picker 暂存目录只在实际选择文件后创建，由当前控制器负责排空与清理；持久文件和引用由 Rust 拥有。

恢复和清空先取消未接纳工作并排空已经接纳的写入、导入和读取。应用通过共享原生拥有者协调文件句柄与存储维护；失败后重新读取实际存储，不能用旧内存复活已经清除的内容。

备份中的附件元数据随聊天保存，二进制单独选择；未携带的文件在恢复后保持缺失。恢复前的空会话草稿只在全部恢复完成后丢弃。
